## 1. Reconstruction du catalogue ordre-K (navigation de l'arrangement relevé)

### 1.1 `prototype/order_k_bfs.hpp` (911 lignes) — ancêtre, faux hors position simple

**Rôle.** Première tentative de calcul du catalogue des sphères critiques de rang fermé ≤ s_max par **parcours du ≤k-niveau de l'arrangement d'hyperplans relevés** dans R⁴ (lifting `phi(p) = (p_x,p_y,p_z,|p|²)` ; une sphère devient l'hyperplan `x_4 = 2c·x − (|c|²−r²)` ; niveau du sommet = nombre de points strictement intérieurs ; **rang fermé = 4 + niveau**).

**Algorithme/structures.**
- **Pinceau** des sphères par un triangle (a,b,c) : centres sur la droite `c_0 + t·u`, `u = (b−a)×(c−a)`. Toute la navigation repose sur l'identité *sans rationnels ni divisions* :
  `signe(t_z − t_w) = o(w) · [w intérieur à sphère(a,b,c,z) ? +1 : −1]`, avec `o(z) = signe(orient3d(a,b,c,z))`.
- Prédicats **entiers exacts en i128**, bornes documentées pour u16 : mineur 3×3 < 6·2^51 < 2^53,6 ; colonne relevée < 3·2^34 < 2^35,6 ; déterminant InSphere 4×4 < 2^91,2. Le signe d'`in_sphere_side` est **calibré** sur un cas explicite (tétraèdre régulier centre (2,2,2), rayon² 3) — une inversion de signe avait été trahie par le *nombre* de tétraèdres Delaunay (57 pour 120 points = Delaunay du point le plus éloigné), pas par l'accord force-brute/parcours (qui partagent le prédicat).
- **Germe** : face de l'enveloppe convexe (lex-min, emballage 2D, rotation), demi-espace vide en t=−∞, premier lot rencontré décrété niveau 0.
- Sommet = **coquille entière** (`Vertex{shell trié, level}`) : les cosphéries sont traitées, arêtes indexées par les C(m,3) triplets de la coquille. Transport du niveau : ±(ce qui entre/sort).
- Critère de criticité **unifié** : une boule est critique ssi elle est la **miniboule de sa coquille** ; support HGP = support de la miniboule ; parcours jusqu'au rang s_max+2 (une arête q2 rejoint un sommet en deux pas de pinceau).
- `OrderKStatistics` avec `static_assert(sizeof == 16·sizeof(long long))` dans `absorb()` : un champ ajouté non sommé casse le build (« compteur muet = branche morte »).
- **Chemin rapide** : `Grid` uniforme (CSR par cellule) + `outward_ball` (sphère exacte convertie en flottant avec marge `×1.0000001 + 1e-6`), amorce le long du pinceau (pas doublés, 40 tours), **certification par l'union des deux boules** (entre deux paramètres tout concurrent est dans la différence symétrique), repli exhaustif final « jamais un faux vert ».

**Statut : réfuté.** L'en-tête d'`order_k_flats.hpp` établit que trois énoncés fondateurs sont faux hors position simple : (1) le rang fermé n'est pas un potentiel de parcours (le **cube cosphérique** : coquille 8, niveau 0, rang 8 — coupé avant navigation, perte des 12 boules diamétrales) ; (2) la variation de niveau entre voisins n'est **pas** ±1 hors position simple ; (3) le germe « décrété » niveau 0 est faux : fixture u16 à 5 points `(4,1,0)(14,19,0)(4,17,0)(17,9,0)(15,8,19)` → germe de niveau réel 1, niveau transporté passant sous zéro. La marge flottante de `outward_ball` est aussi réfutée (voir 1.2). Le fichier survit uniquement comme **sujet du juge M1** (`oracle_main.cpp`).

### 1.2 `prototype/order_k_flats.hpp` (2 819 lignes) — la navigation corrigée, le cœur mathématique v3

**Rôle.** Remplace le BFS : navigation **multiplicitaire** exacte du sous-graphe `{l ≤ k_nav}` de l'arrangement relevé, catalogue par récolte des sous-ensembles de coquilles, index spatial certifié, reverse search sans état, test de « propriétaire » remplaçant la table de déduplication.

**Les quatre grandeurs** (à ne jamais confondre) : pour un sommet v, `B(v)` (ensemble intérieur strict, **transporté** et jamais recensé), `S(v)` (coquille complète), `l(v)=|B(v)|` (niveau strict), `rho(v)=l+|S|` (rang fermé = **filtre de publication seulement**).

**Théorèmes portés par le code** (audits cités dans les commentaires) :
- **Théorème de propriétaire** (`AUDIT_VOIE_MULTIPLICITES_ORDER_K.md` §6) : tout support U de q points (2 ≤ q ≤ 4) dont la sphère a un rang fermé ≤ s_max est contenu dans la coquille d'un sommet de niveau ≤ s_max − q ≤ **s_max − 2**. D'où le plafond de navigation `k_nav = s_max − 2` ; les singletons sont publiés à part.
- **Connexité de `{l ≤ k}`** DÉMONTRÉE (`AUDIT_CONNECTIVITE_ORDER_K_A8111F0.md`) par descente polyédrale (P_B pointé, une contrainte de B porte une facette) + P_vide pointé au niveau 0 — sans supposer ni le relèvement parabolique ni la simplicité. Un seul germe suffit.
- **Arêtes = flats fermés de rang trois** : bijection avec les **plans distincts** engendrés par ≥3 points non alignés de S(v), pas avec les C(m,3) triplets. Transition exacte : `S(w) = C(F) ∪ A` (fermeture du flat ∪ lot d'ex aequo), transport de B(v) **par lots**.
- **Germe certifié niveau zéro** : lex-min → emballage xy → rotation autour de (p0,p1) avec classement explicite de l'angle (0 / ouvert / π ; le nuage cosphérique à 7 points `(26,30,33)…(35,31,30)` montre qu'`orient3d` ne voit un plan qu'à π près) → dans le plan support, **triangle de Delaunay du sous-nuage coplanaire** en deux passes totales (le potentiel « rayon décroissant » est FAUX : fixture `A=(0,0,0) B=(0,3,0) C=(2,1,0) P=(1,1,0) Q=(1,1,2)`, P intérieur au cercle de ABC (prédicat −72) mais les quatre rayons carrés valent 5/2 ; le bon ordre est l'**angle inscrit**, ordre total d'un même côté de l'arête d'enveloppe) → premier lot depuis le demi-espace vide. Chaque étape vérifiée, échec = `kSeedFailed` avec `seed_failure_stage` (1..11).
- Prédicat neuf `in_circle_coplanar` : déterminant 4×4 avec ligne `(u,0)`, u = (b−a)×(c−a) ; signe invariant par échange b/c ; calibré (centre (1/2,1/2,0) → −1/2) ; **borne 2^108,8**, tient en i128 *seulement* sous la grille déclarée.

**Domaine et statuts.** `kDeclaredGridMaximum = 65535` gardé **dans la lib** (pas dans le CLI : un appelant à 10⁹ déborderait i128 avant tout prédicat). `CloudStatus` remplace le fourre-tout `out_of_domain` : `kOk / kAffineDimensionBelowThree (voie directe exhaustive) / kTooFewPoints / kSeedFailed / kInvariantViolated / kDuplicateCoordinates (refus explicite : deux points confondus rendent le support canonique dépendant de la numérotation, fixture (0,0,0)×2…) / kOutsideDeclaredGrid / kOrderOutsideContract / kSinkStopped (arrêt volontaire du consommateur, distinct d'un invariant rompu)`. `s_max` borné par `mhgp::kMaxRank` (=32) — donc `|B(v)| ≤ 30` est un **théorème du contrat**, exploité par le noyau device.

**`CertifiedIndex`** — kd-tree sur boîtes entières (feuille 16, `nth_element` sur l'axe le plus étendu), avec le contrat : « le flottant ne peut qu'ajouter du travail ».
- La grille à maille fixe est abandonnée : une boule vide mais grande coûte (R/maille)³ cellules.
- **La marge flottante a été réfutée** : quatre points u16 `(32767,32767,0)(57863,57862,0)(7672,7673,0)(60104,30135,1)` donnent une sphère `den=2`, rayon ~10^18 — l'élagage flottant supprimait LA RACINE. Chemin rapide **gardé** : autorisé seulement si centre et rayon < 2^20 (`kFastPathBound`), marge d'un demi ; sinon prédicat **exact** boîte–boule : `den²·dist(c,Q)² = Σ g_j²` comparé à `N = |num|²` en `BigInt<4>` (bornes : C_j, g_j < 2^91, somme < 2^184).
- Requêtes : `closed_ball` (appartenance finale décidée par `mhgp::sphere_side` exact, l'égalité — la coquille — conservée) ; **`sign_disagreement`** entre deux sphères du même pinceau : désaccord **ternaire** de `sphere_side` (pas la différence symétrique des boules fermées — elle perdrait « coquille à une extrémité / intérieur à l'autre ») ; élagage seulement si le nœud est certainement du même côté des deux, mince dès que l'événement est proche (une sphère de sliver est énorme mais son *désaccord* est mince) ; `box` entière pour l'amorce. Pile fixe 128 + descente récursive sur saturation (l'ancienne `box` **omettait un sous-arbre en silence** sur pile saturée — corrigé).
- **Aucun compteur `mutable` dans l'arbre** : data race confirmée par ThreadSanitizer dans `sign_disagreement` (audit 50 k, sortie 66) quand la topologie partagée était écrite par des méthodes `const`. Les métriques (`IndexMetrics`, nodes/leaves visités) sont portées par l'appelant.

**Requête de voisin `neighbour_along`** : amorce = `B(v)` (transporté, gratuit) + pavé entier doublé depuis un sommet de la base (mesures : partir du rayon de la sphère courante divise les tours par 4 mais rapporte 5× plus de candidats payés en prédicats exacts — 22,9 s contre 13,7 s à n=800 ; le pavé part petit, `half=4`, et double) ; certification par `sign_disagreement` itéré (≤8 tours, chaque nouveau meilleur a son paramètre entre les deux précédents) ; **repli exhaustif compté** (`exhaustive_scans`, distinct de `full_grid_sweeps`). Scratch d'**époque** (`NeighbourScratch`, 64 bits) au lieu d'un `vector<char>(n)` zéroé par appel — le verrou de débit de l'audit 50 k.

**Reverse search (Avis–Fukuda, Gate D)** : parent unique **calculable au sommet seul**, donc énumération *stateless* — pas de `seen`, pas de table partagée, pas d'écriture concurrente : « c'est cela, et non les quarante-huit cœurs, qui rend un front d'onde GPU possible ».
- Direction d'un flat sans grands entiers : `d = (u, 2u·a)` et `a_i·d = −2·orient3d(a,b,c,p_i)` — le signe tangent se lit avec le prédicat que le pinceau évalue déjà. Les surcharges `tangent_sign(i128,…) = delete` transforment la **troncature implicite i128→int** (signe faux dès l'échelle u16 1291, `-INT_MIN` UB à 1025) en erreur de compilation.
- Admissibilité d'un couple (base ordonnée, direction) : rester dans la chambre (aucun membre de coquille rendu intérieur) + faire croître `L_h` (h = min B(v)) ou, au niveau 0, décroître `Q_r` (somme des **valeurs** d'orient3d sur la base indépendante du germe — les quatre premiers de la coquille ne suffisent pas : sur grille saturée, quatre coplanaires cassent l'unicité du minimum, mesuré 1 nuage/600).
- **Le premier admissible EST le minimum** : trois points d'une sphère ne sont jamais alignés ⇒ base canonique = trois plus petits de la fermeture ⇒ `for_each_flat` livre les flats en ordre croissant de clef — sortie précoce légitime (l'énumération de parent dominait : ~5,7 énumérations complètes de flats par sommet).
- `decide_child` : **aucune requête de voisin de retour** — adjacence de pinceau symétrique, on énumère les couples du candidat jusqu'à la clef de retour (couple admissible antérieur ⇒ rejet ; clef atteinte et admissible ⇒ accepté ; régression d'ordre/bases disjointes/retour inadmissible ⇒ `kBroken` = contradiction). L'ordre strict d'énumération est **vérifié** à chaque pas, pas supposé.
- Curseur de reprise (i,j,k,dir) dans la pile : rebranché après une fausse « optimisation nulle » (le curseur n'était pas branché ; « une identité exacte de compteurs est le signe qu'un code neuf ne s'exécute pas ») : 192 570 → 151 708 fermetures (≈1,2×).
- `reverse_search_stream` : sortie **streamée** vers un sink (mémoire = pile + scratch, high-water `reverse_live_high_water` **publié**), couronne (`crown_depth`) pour distribuer des sous-arbres avec le même `root_base` (front d'onde CPU), interruption du sink = `kSinkStopped`.

**Propriétaire (`is_owner`/`owner_rays_ok`)** — remplace la dernière table globale Θ(sortie) (`emitted`) : v possède U ssi `U ⊆ S(v)`, `B(v) ⊆ B_U`, `B_U ⊆ B(v) ∪ S(v)`, et aucun rayon extrême admissible du cône tangent **signé** n'améliore `(g_U·d, d0..d3)` lexicographiquement. Gradient sans O(n) : `A_X` précalculé, `g_U = A_X − Σ_U a_u − 2Σ_{B_U} a_i`. Arité 4 : aucun rayon ; arité 3 : deux orientations du pinceau ; arité 2 : plans U∪{s}.

**Catalogue (`flat_catalogue`)** :
- Singletons en temps constant sous refus de doublons (l'ancien census global coûtait n² = 2,5 G classifications à 50 k **avant le germe**).
- Récolte par sommet : coquille entière + paires + triplets (les 4-sous-ensembles sont **redondants** : démontré dans le commentaire), avec **préfiltre de propriété** en O(|B(v)|) comparaisons exactes par candidat (tout intérieur de v doit être intérieur à la boule candidate).
- **Support canonique GÉOMÉTRIQUE** : plus petite cardinalité puis plus petit sous-ensemble pour l'**ordre des coordonnées** (trier la coquille par (x,y,z) avant `miniball_of`) — trié par identifiants c'est équivariant mais pas invariant (mesuré : une permutation change la sortie sur `cube`, `coplanaire_pur`…). Le cube cosphérique a 4 supports de cardinalité minimale (diagonales) mais **6** supports minimaux pour l'inclusion.
- Mode owner : rejet des supports non canoniques + `is_owner` du sommet ; l'arité 4 (récoltée depuis la coquille entière) passe par une voie séparée (`from_shell`) sinon toute coquille cosphérique la perdait ; la voie directe (dim < 3, n < 4) et les singletons **gardent `emitted`** (aucun sommet, aucune notion de propriété — la première version les supprimait en silence).
- **Ordre de sérialisation canonique** : lexicographique sur les QUATRE cases de `support` (queue à −1), jamais « par arité d'abord » (`ForestNode::source` est un indice : la divergence serait publique).
- `verify_census` : census exact (recalcul coquille + intérieur depuis la sphère) **fail-closed** — l'ENSEMBLE intérieur est comparé, pas son cardinal, et une contradiction vide la sortie (« pas de préfixe partiel »).

**`FlatStatistics`** : ~50 compteurs, `static_assert(sizeof == 51·sizeof(long long))`, distinctions instructives : `full_grid_sweeps` ≠ `exhaustive_scans` ; high-waters vrais (`shell/closure/touched/batch/interior_high_water`) relevés à chaque écriture — « la taille finale ne prouve rien » ; `dedup_table_high_water` à l'insertion ; `reverse_reject_backward` (refus en O(m), sans énumération) vs `reverse_reject_by_parent`.

**Prédicats** : tout est **exact** (i128 / BigInt<4>) ; le flottant n'apparaît que dans le chemin rapide de l'index, gardé et fail-open.

### 1.3 `prototype/order_k_device_core.hpp` (349 lignes) — le même chemin de décision, borné et device-portable

**Rôle.** Réécrit le chemin de décision de la reverse search sous contraintes device : aucune allocation/STL, capacités fixes, `MHGP_HD`, mêmes prédicats entiers.

- **Capacités** : `kMaxShell = 32` (choix, PAS un théorème — une coquille cosphérique peut être Θ(n) ; dépassement = **refus rejouable** compté) ; `kMaxInterior = kMaxRank − 2 = 30` (**théorème du contrat**, `static_assert`) — un intérieur de 31 est une **entrée malformée** (`kInteriorAboveContract`), pas un refus de capacité (l'ancienne capacité `kMaxRank` traitait ces impossibles comme des admissions ordinaires). `kMaxClosure = kMaxShell`.

## 2. Le fold saturé : des générateurs aux K forêts

Sémantique commune (théorèmes S.1–S.5 de `docs/math/TOUR_BOULES_SATUREES.md`) : un **générateur** est un saturé `S = X ∩ B` (la liste `members` d'une sphère critique), actif à son niveau exact ; à l'ordre k, le graphe `H_k` (un sommet par générateur de taille ≥ k, arête ssi `|S∩T| ≥ k`) a les mêmes composantes que `Gamma_k` ; couverture d'une composante = union de ses saturés. **Famille complète** exigée pour l'exactitude (`s_max ≥ n`) ; sinon raffinement S.6 (aucune fausse connexion, fusions manquantes possibles) à **déclarer**.

**Protocole de lot Q1.2** (partagé par toutes les formes et par le juge) : lots = classes d'égalité **exacte** de niveau (`mhgp::sphere_cmp_beta` sur la représentation entière des sphères — jamais un flottant), coupe stricte **figée avant** toute activation (capture d'époque : nœud public + taille de couverture + témoin par racine au premier contact), toutes les activations du lot appliquées, unions, puis classification **par composante finale** selon le nombre de racines strictes distinctes : 0 = naissance, 1 = continuation, ≥2 = multifusion.

**Transcript Gamma par marquage q_min** : seules les racines atteintes par un **générateur d'événement** (`|M| ≥ k` et `q_min ≤ k+1`, q_min lu dans `n_support` — provenance **certifiée par le juge**) produisent un événement public. **Garde fail-closed** : une naissance marquée exige `q ≤ k` (violation = refus sous famille complète, compteur sinon). **Témoin canonique** `ω_k(R) = min lex des first_k(M)` (les k plus petits identifiants), initialisé à l'activation, propagé au min à chaque union — deux racines ne partagent jamais un témoin (lemme d'unicité). `GammaEventRecord` = (niveau, témoin fermé, témoins stricts absorbés triés/dédupliqués, **saturés des boules marquantes**, type) : la forme forte comparée record à record — « une couverture d'observations n'est PAS un identifiant de composante ».

### 2.1 `saturated_fold.hpp` (1 138 lignes) — la forme de vérité G² + le join par postings

- `build_saturated_fold` : jointure **naïve O(G²) par lot** (intersection de listes triées, sortie précoce au seuil k) — « la forme de VÉRITÉ, pas la forme d'échelle ». DSU (compression par moitié), couverture par `std::set` fusionnée petit-dans-grand, partitions matérialisées **sur demande** seulement (les stocker par lot coûtait O(niveaux·G·|S|) et « tuait le pipeline dès n=200 »). Vérification fail-closed du catalogue reçu (tranches de pool, membres triés sans doublons).
- `build_gamma_forest` : fonction **PURE** des records → K forêts (naissance = feuille ; continuation = re-témoignage du nœud ; multifusion = nœud interne + rattachement) ; `orphan_witnesses` (famille partielle) et `invalid_records` (validation avant lecture : type ∉ {0,1,2}, arité stricte incompatible, témoins non triés — la porte exige 0).
- `TranscriptMutants` (6, vivant dans le code produit pour que la porte prouve qu'elle mord) : `skip_first_event_marker`, `mark_first_redundant` (q>k+1), `drop_first_strict_witness`, `stale_witness_after_union`, **`swap_marking_in_batch`** (le mutant compensé exact : triples par niveau inchangés PAR CONSTRUCTION, seuls records/témoins bougent), `extra_marker_in_marked_root` (seul le digest des boules marquantes le voit).
- **Join par postings** (`build_saturated_fold_postings`) : théorème de réduction — pour chaque point x, émettre une occurrence par paire non ordonnée de `P_x` puis réduire donne exactement `w(M,N) = |M∩N|` ; arête d'ordre k ssi `w ≥ k`, activée au lot du **plus tardif**. **Identités de reçu** : par lot `occurrences émises = Σ poids réduits` ; globales `Σ|P_x| = Σ|S|`, `P_post = Σ_x C(d_x,2) = Σ poids`, `P_post réel = P_post PRÉDIT` — toute violation refuse le fold ENTIER. **Préflight** avant émission, arithmétique u128 plafonnée à 2^62, pic conservateur (32 o/occurrence du plus gros lot + 8 o/posting + états 40·K/générateur + couvertures 64·K/membre) écrit AVANT le refus de budget (« manifeste du refus »). **Identifiants compressés** (rang dans l'univers trié — un PointId clairsemé coûtait O(max) et pouvait déborder). Mutants nommés (§6 de la note) : `strict_threshold` (w>k), `skip_new_new`, `omit_last_posting`, `truncate_membership` (membres tronqués à K+1 — interdit expressément), `collect_silent` (un lot silencieux porte des connexions futures), `sequential_equal_levels` (atomicité Q1.2).

### 2.2 `saturated_fold_global.hpp` (490 lignes) — la forme GPU-reprenable

CSR complet des postings construit après le préflight ; **émission parallèle par chunks** (découpage par préfixe de masse triangulaire ≈ P_post/T par thread, buffers locaux triés) ; tri global + réduction ⇒ table pure de l'entrée : **un run à T threads et un run à 1 thread rendent le MÊME fold bit à bit** (« contrat à deux digests », la porte l'exige). Tri des arêtes par (lot d'activation = max des deux, clef canonique), rejeu séquentiel DSU identique au protocole. Pic en **P_post entier** : observé n=200 → **385 M d'occurrences**, OOM silencieux avant le refus déclaré (audit 39cf76e — séquence exigée : degrés u128 → manifeste → budget → CSR → émission).

### 2.3 `saturated_fold_faceowner.hpp` (582 lignes) — l'étoile par signature de k-face

**Le théorème de masse** : deux générateurs se touchent à l'ordre k ssi ils contiennent une même **signature de k-face** ; le biparti générateurs–signatures a les mêmes composantes que H_k ; pour chaque signature F, une **étoile** centrée sur `owner_k(F)` (l'incident de niveau exact minimal, tie-break canonique par rang d'activation) remplace sa clique à toutes les coupes — l'owner est actif avant (ou dans le même lot que) chaque autre incident, aucune fausse arête. Masse `I = Σ_k Σ_M C(|M|,k)` au lieu de `P_post = Σ_x C(d_x,2)` : **mesurée 23,5× plus petite à n=200 (16,4 M contre 385,6 M)**.

- **Oracle borné** : signatures matérialisées, `k ≤ 6`, identifiants denses < 2^21 pour l'empaquetage u128 (clef = concaténation 21 bits/id). La variante produit serait la recherche à la demande (§6).
- **Un ordre à la fois** (pic borné par le plus lourd ordre seul), émission-tri-owner puis **rejeu** des lots (même capture d'époque/marquage/records). Support **validé** à l'entrée (cardinal ∈ [1, min(4, rang)], trié, inclus dans les membres).
- Identités **par ordre** (audit 56e76c6 : une compensation entre deux ordres ne passe plus par le total) : `I_k = binomiales prédites`, `branches = I_k − signatures`, `Σ dédupliquées = unions tentées`.

### 5.6 `oracle/jung_dual_judge.hpp/.cpp` (84 + 198) — juge PRIMAL du certificat de couverture

Répond au contre-audit du sujet `prototype/jung_dual.hpp` (voie duale : choix de poids, testait `A² > 2R` ; son selftest ne comparait que k=1 — « ce n'est pas un oracle de couverture »). Le juge **primal** ne choisit aucun poids : il **minimise directement**.
- Paramétrage : centre `c = m + w`, `s = 2w ⊥ d`, `u_z = a+b−2z` ; z mauvais ssi `2s·u_z ≥ g_z`, `g_z = D − |u_z|²`. Domaine = disque de Jung `|s|² ≤ D/2` (q4), `D/3` (q3).
- Le groupe couvre la lane ssi `min{|s|² : s·d=0, 2s·u_z ≥ g_z ∀z} > rayon²` — minimum d'une quadratique sur une intersection de demi-plans : **nombre CONSTANT de candidats exacts** pour ≤3 témoins : origine (admissible ssi tous `g_i ≤ 0` ⇒ ne couvre pas), un bord actif (`|s|² = (D/4)·g_i²/K_ii`, admissible ssi `g_i·K_ij ≥ g_j·K_ii` ; le cas 1-bord **redonne le prédicat ponctuel (g,Q)** : `g² > 2K` — première vérification de cohérence), deux bords actifs (`Δ = K_ii·K_jj − K_ij²`, `N = g_i²K_jj − 2g_ig_jK_ij + g_j²K_ii`, sommet minimum ssi multiplicateurs de Lagrange ≥ 0, admissibilité du 3ᵉ bord `l_iK_il + l_jK_jl ≥ g_lΔ`).
- Verdicts : `q4 : N > 2Δ`, `q3 : 3N > 4Δ` ; région mauvaise vide ⇒ couvre ; `kUnknown` **jamais un accord** (dégénérescence explicite).
- Largeurs : `K_ij = D(u_i·u_j) − (u_i·d)(u_j·d)` atteint 70 bits sous u16 ⇒ Δ, N ≈ 140 bits : « i128 ne suffit pas : tout passe par BigInt » — autre unité de traduction, autre arithmétique, autre objet mathématique que le sujet.

## 6. Conventions transverses (l'ossature de test v3)

- **Profil d'entrée** : u16 quantifié `[0, 65535]` seulement ; doublons de coordonnées = refus explicite (`kDuplicateCoordinates`) ; dégénérescences = refus nommé, **jamais un jitter** ; toutes les bornes de largeur (2^91,2 ; 2^108,8 ; 2^184 ; 5,8e30…) sont dérivées de cette grille et gardées à la frontière de la lib.
- **Codes de sortie exacts** : 0 OK ; **1** = désaccords du juge ; **2** = campagne/CLI refusée avant calcul ; **3** = plancher/invariant violé (ou refus de préflight) ; **4** = mutant tué. Aucun crash par signal. CLI strictes : tout argument inconnu refusé.
- **Planchers `--min-*`** contre le vert-par-vacuité (supports, ancres, prunes, décidés, niveaux, records…) ; compteurs d'échantillons (`samples`, `theta_anchors_active`) pour distinguer « démontré nul » de « jamais atteint ».
- **Mutants nommés** (`--inject`, `--force-*`), chacun ciblant UNE décision, vivant dans le code produit, exigeant un juge (`--inject` sans `--verify` = refus ; mutant sans effet = code 3 « MUTANT SURVIVANT ») ; les mutants « compensés » (swap_marking, duplicate_signature) prouvent que la porte forte (records, identités de préflight) mord là où les agrégats restent verts.
- **Équivariance par permutation** des PointId (3 ordres dans la porte Gabriel ; invariance géométrique du support canonique) ; conventions **géométriques** (coordonnées) plutôt qu'identifiants partout où la sortie est publique.
- **Compteurs** : `static_assert(sizeof)` sur `absorb()` ; sommes vs high-waters séparés (atomicAdd vs atomicMax sur device) ; ledger complet comparé nommément entre moteurs (« un compteur absent n'est pas un compteur nul »).
- **Fail-closed partout** : validation hostile des entrées (catalogue, offsets binomiaux device, Forest du sujet), refus atomique avant calcul, manifeste de préflight publié même sur refus, sortie vidée sur contradiction (jamais de préfixe partiel), `kUnknown` jamais un accord.
- **Capacité fixe ⇒ refus explicite compté, jamais troncature** ; refus device = rejeu hôte ; représentation binaire stable (queues à −1) pour les digests.
- **Parité hôte/device par construction** : une seule fonction `MHGP_HD` compilée deux fois ; le différentiel détecte compilateur/matériel, pas l'algorithme ; symboles CUDA définis seulement par l'unité .cu (pas de faux chemin device).
- **Digests** : diagnostiques (hash de flux du transcript — l'ancien digest sur partitions seules devenait constant), le digest scientifique reste un travail déclaré. Déterminisme multi-thread = « contrat à deux digests » (T threads ≡ 1 thread bit à bit).

## 7. Synthèse pour la CONCEPTION V4

### 7.1 Idées algorithmiques qui méritent de survivre

1. **La réduction par arête maximale (Lemme A) est déjà écrite et jugée** : tout le groupe `anchor_*` est l'ancêtre direct de la feuille de route V4 (q2/q3/q4 depuis l'arête maximale). À reprendre tels quels : les **boules de milieu universelles** (q2 `u·u<D2`, q3 `3u·u<D2`, q4 `15u·u<4D2`, en coordonnées quadruples entières), les **seuils de mort paramétrés `smax−q+1`** (les valeurs figées 10/9/8 sont réfutées), la **lentille** `B(a,D)∩B(b,D)` avec `|x−y| ≤ D` pour q4, la **positivité q3 = triangle strictement aigu** (3 dots stricts ; angle droit ⇒ q2) et **q4 = même côté strict sur les 4 faces** via `Δ(c−p)+Y`, la **BallForm relative** `σ(z) = Δ|z−a|² − 2(z−a)·Y` avec ses bornes i128 documentées par lane, et l'**émission exacte-une-fois par propriété d'arête maximale canonique** (plus longue, tie-break (min,max)) — vérifiée par l'identité « aucune clé en double ».
2. **L'élimination « par h témoins »** existe sous deux formes complémentaires : (a) le **certificat de front par boule témoin commune** sur l'arbre (si `15·ext2 ≤ 2G`, boule rayon² G/60 dans le spindle de toute paire du produit ; minorations rationnelles strictes 20000/11547/10327 ⇒ ne coupe jamais à tort) — c'est le germe du dual-tree h_a/h_b de la V4 ; (b) les **marges de site entières fail-open** `Llow/Uhigh` (Cauchy–Schwarz + `isqrt_i128` exacte) avec la **mort par budget au plus tôt** (compter les `Llow>0` = minorant exact de p, tuer l'ancre dès dépassement). Le juge **primal Jung** (QP à nombre constant de candidats exacts : origine / 1 bord `g²>2K` / 2 bords `N>2Δ` avec Lagrange) est l'oracle indépendant de tout certificat de couverture de groupe — largeurs ~140 bits ⇒ BigInt.
3. **Parité hôte/device par construction** : un seul fichier de pipeline `MHGP_HD`, scratch à capacités fixes par slot, drapeaux OR-és atomiques, refus-jamais-troncature, mode compte-seulement puis stockage, compteurs en registres versés une fois (sommes/high-waters séparés). C'est la seule discipline qui a tenu (la garde de densité a cassé l'ABI en la violant).
4. **Le patron GPU émission-tri-owner** (`faceowner_device_kernel.cu`) pour l'identification d'événements : dé-rangement de combinaisons par binomiales en `__constant__`, clés empaquetées 21 bits/id, tri thrust qui **porte** la sélection (owner en tête de groupe), mark_heads + scan + copy_if, contrat = flux d'arêtes comparé arête par arête, temps par phase. La validation hostile des offsets (masse binomiale exacte par générateur) est le garde-fou anti-boucle infinie.
5. **La reconstruction des K forêts** : protocole de lot Q1.2 (lots par égalité **exacte** de niveau via `sphere_cmp_beta` entier — jamais un flottant), capture d'époque de la coupe stricte, classification 0/1/≥2, témoin canonique `first_k` propagé au min, prédicat d'événement `|M| ≥ k ∧ q_min ≤ k+1` avec garde `q ≤ k` sur les naissances, `GammaEventRecord` comme objet fort de comparaison, forêt = fonction pure des records. La **factorisation face-owner** (I = ΣC(|M|,k), 23,5× sous P_post) et le **fast path des q attachés** (`S_u = (U\{u}) ∪ T`, clé de boule = centre réduit par pgcd) sont les deux voies d'échelle du join — la seconde exige la famille complète et un lookup fail-closed.
6. **Le kd/LBVH certifié** : le flottant ne peut qu'**ajouter** du travail (chemin rapide gardé sous 2^20, sinon prédicat boîte–boule exact en BigInt<4>) ; la requête de **désaccord de signe ternaire** entre deux sphères (et non la différence des boules) pour certifier « aucun événement entre deux paramètres » ; l'époque de scratch au lieu du zeroing O(n) ; jamais de compteur mutable dans une structure partagée.
7. **Conventions publiques** : support canonique **géométrique** (cardinalité minimale puis ordre des coordonnées), ordre de sérialisation lexicographique sur les 4 cases, refus des doublons de coordonnées, statuts nommés (jamais de fourre-tout), distinction troncature volontaire (`kSinkStopped`) / contradiction (`kInvariantViolated`).

## Questions ouvertes / ambiguïtés

1. **WSPD absente de v3.** La feuille de route V4 (Callahan–Kosaraju, s=6/8/10, rectangles A×B, dual-tree h_a/h_b « jamais en quadratique A×B ») n'a **aucune implémentation v3** : le front v3 est mono-arbre (un point d'ancre a contre un LBVH), et les paires candidates sont énumérées `b > a` par point. Les briques transférables (boules témoins, lanes, marges) existent, mais la certification « par paire de nœuds (A,B) » (témoins dans A et dans B) devra être re-démontrée — le certificat v3 (`15·ext2 ≤ 2G` avec G = dist(a, boîte)) est ancré sur un **point**, pas sur une boîte source.
2. **Bornes i128 des lanes sous WSPD** : les bornes v3 (σ ≤ 5,8e30 etc.) supposent l'origine du repère au point a du support. Si la V4 évalue depuis des représentants de boîtes, les bornes sont à refaire.
3. **`kMaxRank = 32` vs domaine smax de l'ancre** : `anchor_source.cpp` accepte `smax ≤ 2 + kMaxEnvelopeDepth = 34` alors que le catalogue navigué refuse `s_max > 32`. Incohérence de domaine mineure entre les deux chantiers, non tranchée dans les fichiers lus.
4. **Le contrat K=10 < 100 ms** : aucun chiffre v3 ne s'en approche ni ne le contredit — les seuls temps lus sont des diagnostics (navigation 13,7 s à n=800 ; kernel d'ancre chronométré mais valeurs non gravées dans les sources lues ; faceowner device : temps par phase publiés par le harnais, non consignés ici). Le dimensionnement V4 (n = 8000/16000/32000, dizaines de millions) part donc sans base de temps v3 exploitable, seulement avec des **masses** (I_k, P_post, high-waters d'ancre à n=12 500).
5. **Statut de réception de `fast_exaequo`/`factorise_exaequo`** : les commentaires citent des réponses d'auditeur du 11/8 mais je n'ai pas lu les audits correspondants ; je ne peux pas certifier que la neuvième forme (fast multi-lot) a été reçue verte.
6. **Le front d'onde GPU de la reverse search** : `order_k_device_core.hpp` fournit la décision bornée, mais aucun kernel `.cu` correspondant n'est dans les fichiers lus — je ne sais pas si le parcours complet a jamais tourné sur device.
7. **`shell_extra` dans la clé de contrat V4** : v3 publie `p` et `extra` (coquille surnuméraire) par support et le différentiel compare `extra` explicitement. La V4 doit décider tôt si ses événements portent la coquille surnuméraire (rang fermé) ou seulement p — le fold en dépend (lots d'égalité exacte).
8. **Familles de nuages** : `cloud_families.hpp` (uniform/terrain/scanline_single_pass/scanline_overlap_multiecho/eight_clusters, `cloud_family_default_coord` — emprise volumique 1e-3 pour uniform, aréale pour terrain) n'était pas dans la liste de lecture ; les régimes « uniforme/terrain/clusters » de la V4 y ont déjà des générateurs partagés CPU/device à reprendre.
9. **`q4seed_axis_topr4.hpp` / `prefix_index.hpp` / `morton_lbvh.hpp` / `validated_hybrid_sidecar.hpp` / `sealed_source.hpp` / `parallel_catalogue.hpp`** : dépendances citées mais hors liste — le théorème d'axe (`r4−p ≤ 8` groupes) et la construction LBVH Morton exacte mériteraient une lecture dédiée avant de figer la conception V4 du dual-tree.
10. **Vocabulaire « rang fermé »** : la porte Gabriel compte les extrémités (Φ ≤ 0, rang de la paire (p,q) inclut p et q), l'ancre compte `p = |I_B|` strict + q + extra. Les deux conventions coexistent dans v3 ; la V4 doit en choisir une et la graver dans le glossaire avant d'écrire un seul seuil.
