16. **Largeurs entières u16** : Gram `|Phi| < 432·65535⁸ < 2¹³⁷` (i192) ; sweep `G`~68, `W`~86, `A_z`~104, `B_z`~51 bits, ratios ~155 bits (i192) ; ApexWellCentered ~174 bits ; `J_f` ~209 bits ; primal `Δ,N` ~140 bits ; SOC64/JungDual ponctuels < 105 bits (i128).

### 2.b Mesures chiffrées et décisions d'architecture

- **Contrat** : 50 000 pts, `K_max=10`, G4, deux familles (uniform, eight_clusters), payload en mémoire épinglée avant arrêt chrono ; `p95<100 ms` principal, `<1 s` secondaire. Repli tranché par l'utilisateur : `K=5` (facteur ~12 sur la masse) puis `1 s`.
- **État CPU** : `78,8 s` à 50k uniform, **aucun objet produit** ; **428 supports/point** (`21 413 140` SupportKey) ⇒ `214 M supports/s` requis pour 100 ms (`4,3·10¹⁰` ops larges/s) ; masse candidate = `6 914×` la sortie ; l'aval manquant est chiffré `1,2·10⁶×`.
- **L'écart candidats/sortie** : `M4 ~ 0,64·C(n,4)` (`1,7e17` à 50k) contre `H4 ~ 30n` (`1,5e6`) — **11 ordres de grandeur** ; profondeur moyenne d'un candidat `~n/2,6` contre seuil 7 (marge `6,6×` à `n=120`, `~2700×` extrapolée à 50k) ⇒ un certificat de profondeur de bloc très conservateur suffit, à coût `O(F4)`.
- **SOC64** : ferme 13–34 % du résiduel selon famille/profondeur, capte `96,2 %` du plafond ponctuel `u` ; +`NONE` central : uniform ×2,06 (`40,45 %`) ; mais pentes `E4` restent `~1,80` sur amas ⇒ voie centrale NO-GO (restreint au sous-système prune). Coût : `7,5–48,6 M` tâches à `n=3000` sans cap ; branché : `E4 -18 %`, temps `+15 %`.
- **Résiduel = artefact** : `72,5–92 %` des paires laissées ouvertes sont fermables exactement (relaxation de boîte, pas géométrie) ; le budget ne borne jamais (`tronques=0`).
- **WST4CandidateCover** : `1,05e9` blocs à `n=32000` (32 736/point), pentes finissant `1,16/1,33` (uniform) mais `2,30` (amas) ; `k_t` croît `15,4→35,1` ⇒ **filtre d'acuité avant le produit = condition de viabilité**.
- **Sélectivités** : acuité retient `7,3–7,8 %` des quadruplets mais `>99,998 %` des **blocs** ; seul le rang est sélectif. Repli `smax=11→6` mesuré : `5,35×` (pas 12).
- **Décisions figées** : aucune Delaunay (Q14) ; trois lanes autonomes (mutualisation limitée à partition neutre + index Morton) ; pas de produit carrier×apex matérialisé ; count→scan→fill avec preflight ; `RelevantGP` ⇒ `unsupported_degeneracy` ; profil u16 conservé, binary64 = profil séparé à statut distinct ; ordre statique certificats-bon-marché → SOC coût-aware → split (pas de branchement par famille) ; `warm_e2e` inclut transfert + sortie épinglée ; porte structurelle (zéro allocation ∝ cofaces) avant tout chrono ; à 30 M : baisser `K_max` ou tuiles avec recollement certifié par calottes.
- Matériel : mesures Claude sur poste 2 vCPU (aucun temps qualifiable) ; session CPU 48 cœurs (jusqu'à 147 s par palier amas, `INCOMPLET_OU_TRONQUE`) ; G4 : une tentative avortée avant build (garde `terminationTimestamp`), `TERMINATED` certifié.

### 2.c Bugs, erreurs, rétractations documentés

1. **Ledger SOC additif** (Claude, `wspd_wavefront_probe`) : `cred+soc_cred>=need` sur ensembles non disjoints (`socm` bloquait `SOC→SOC` pas `SOC→central`) ; table publiée à `157,67 %` de masse fermée. Réparé par replay combiné ; invariant naïf `ccred>=cred` lui-même réfuté (419 rectangles) ; forme correcte `ccred >= min(cred,need)`.
2. **`M4_estime` mal nommé** : le sampler v0 mesurait `A4_weak` (owner non appliqué, PENDING inclus) ; v1 encore invalide (censure des lentilles capées, quadrature sans IC, oracle non indépendant et silencieusement sauté — vacuité reproductible : sortie `0` sans ligne oracle).
3. **« `M4=Θ(n⁴)` pour tout nuage » — rétracté** : `two_lines` donne `M4=0` ; l'énoncé recevable est borné aux familles mesurées. Quatrième rétractation de la journée de Claude.
4. **« Un tiers perdu par le budget » — inférence fausse** : `tronques=0, pending=0`, réordonner la descente a un effet nul au bit près.
5. **Identité d'acuité inversée** : `E+X-D=2H` committée, la bonne est `-2H` ; le filtre éliminait de vrais carriers (dont `H=-1` du tétraèdre régulier) ; gains `1,46×/1,62×` retirés.
6. **Rétractation `0A`** : numérateurs q3/q4 de 67–81 bits rabattus en `int64` (UB sous UBSan) ; remplacé par le microkernel Gram (i192).
7. **Sentinelle de coupure** : faux vert `two_lines` (`q2=20` vs 45, ratio 0,007) — le max observé est conditionné par la coupure.
8. **Owner q3 non total** : tie-break sur le seul plus petit endpoint ⇒ `SupportKey` dupliquée (fixture isocèle `(0,0,0),(3,4,0),(4,3,0)`).
9. **Shell tronqué sans fate** (`Q4SeedAxisTopR4`) : capacité 99 pour un shell de 100 ; réparé (`kCapShellTotal=163`).
10. **Census `EXACT` sur `MORT_GAP`/apex profond** : `fixture_mort16` ; réparé à `a369452` (`HORS_DOMAINE`).
11. **Assertion `cand_max<=2*r4`** contredisant le théorème (groupes ≠ IDs) ; retirée.
12. **Mutants d'abord survivants** par fixtures inadéquates : `soc-narrow-i64` (fixture colinéaire), `a8-shell-compte-interieur` (pas de shell persistant exercé), `dual-ignore-weights` (no-op à k=1), `dual-accept-equality` (égalité jamais tirée) — leçon : les fixtures doivent exercer causalement la faute.
13. **`mhgp3v_q4axis_mutant_shell_plateau`** : identités d'entrée non vérifiées (`sites=[7,7]` falsifie `MORT_GAP`) — P0 resté ouvert.
14. Preuve documentaire du minimax `JungDual` inversée (formule codée juste) ; commentaire source périmé sur `kMortGap`.

### 2.d Pistes fermées dans cette tranche

- **Cascade d'arités** (q4 depuis q3 retenus / clique q2 / masque de rang) : fausse, fixtures permanentes (64 points ; q3 rang 12 / q4 rang 4) + mutants `q4_requires_retained_q3`, `q4_requires_q2_clique`, `q4_uses_q3_depth_mask`.
- **Toute structure de Delaunay, ordre 1 inclus** (Q14, définitive).
- **Expansion ponctuelle `arête × porteur (× apex)` pré-rang** : condamnée (pentes 3/4, `M4 ~ 0,64·C(n,4)`) ; « pas de produit carrier×apex » figé.
- **`sum E4` comme proxy de sortie / critère de mort global** : retiré (`two_lines` : `E4=Θ(n²)`, sortie vide) ; reste gate du seul sous-système prune.
- **Voie centrale (prune universel + SOC comme architecture suffisante)** : NO-GO renforcé (pentes 1,80 sur amas malgré SOC).
- **Un troisième certificat ponctuel de boîte** : fermé — SOC64 est à 96,2 % du plafond `u` ; et `u` n'est de toute façon pas la bonne quantité (`u<=p<=d`).
- **Huit groupes disjoints comme décision complète** : réfuté (`p=7 < d=8`).
- **Réordonnancement de descente par proximité** et **élagage `NONE` central comme perte de témoins** : gains nuls mesurés.
- **`JungDual` collectif comme levier** : gain 2–8 % décroissant ; banque de poids remplacée par le primal : gain nul.
- **Sentinelle `0,75·dmax`** comme certificat de complétude : réfutée (fixture permanente `two_lines`).
- **`3B_R`** : remplacé par `2B_R` sharp.
- **Owner `BallKey` pour éviter la génération** : circulaire (utile seulement en aval, RLE/dédoublonnage).
- **Sweep par face comme consommateur systématique** : paierait `C4·n log n` (`~n⁴ log n` sur amas) ; fallback seulement.
- **Coins d'un `FaceBlock` variable comme preuve `ALL`** : interdit (polynômes corrélés non convexes ; mutant `corners_order_implies_all`).
- **Quantification binary64→u16 « transparente »** : impossible sans pont-similarité exact ou certificat par entrée.
- **Inclusion complète des nœuds dans la lentille** (WST3) : coût de surface quadratique ; arrêt à l'échelle du rectangle.
- **Certificats de paire évalués à chaque nœud** : structurellement déficitaires (SOC64 +15 % temps, HCBlockDepth +55 %...).

### 2.e Ce que la V4 doit conserver / éviter absolument

**Conserver :**
1. La **définition normative de la source** (contrat réparé §7 de `NOTE_SOLUTION_CONTRAT_SOURCE_AIGUE`) : lemme miniboule=positivité, ancre arête diamétrale + tie-break `PointId`, fuseaux `W_q` (filtre nécessaire, bloc-exact par 8 coins à `(a,z)` fixés), seuils `h_q=smax-q+1`, requête census `B(m,D)`.
2. **CK/WSPD comme tape exact-once** (`⊔A_i×B_i`, `O(s³n)`), l'ordonnance `count→scan→fill` avec preflight, et les bornes `F3=O(s³η⁻³n)` / `F4=O(s³η⁻⁶n)` avec l'enveloppe **`2B_R` ∩ enveloppes endpoint**.
3. **Trois lanes autonomes** ; mutualisation limitée à l'index Morton et à la partition neutre ; owner arête maximale + carrier aigu primaire (théorème d'existence).
4. Le **filtre d'acuité au niveau bloc AVANT le produit de cellules** (réduire `k_t` : condition de viabilité), avec la bonne identité `H<0` (`E+X-D=-2H`).
5. La cible **output-sensitive** : `H4 ~ 30n` est linéaire ; l'élimination doit se payer par bloc (`F4`), jamais par candidat (`M4`) — c'est le sens exact du « h témoins dans la zone cœur puis h_a/h_b dual-tree, jamais quadratique A×B » de la feuille de route V4. Briques prêtes : cœur commun constant `(d-2S)/2`, `[L_open,U_closed]`, `BlockJungDual` à poids fixes (64 coins exacts), Jung 1D sur l'axe (`J_f`, Helly ≤ 2, 8 groupes), `Corner8BallDepth`/`BlockBallDepth8` (8 coins intérieurs = `ALL`), top-k `p/k` en `O(n)/O(8)`, `TetraDepthBlock` Bernstein/SOS. Et la **hiérarchie `u<=p<=d`** : viser la profondeur `d` (collectif), pas l'universalité `u`.
6. Les **fixtures permanentes** (non-cascade 64 points, cosphérique λ=0, faces obtuses/`-1/12`, two_lines, isocèle owner, `u=6/p=7/d=8`, 97-ties shell, mort-16, cocyclique 384, fixtures d'égalité `2B_R`) et la discipline de portes : codes de sortie exacts 1/2/3/4, planchers anti-vacuité, mutants causaux, équivariance, juge à arithmétique indépendante, `PENDING`/fates typés jamais de troncature silencieuse.
7. Les **largeurs entières prouvées** (i128 vs i192 par prédicat) et le pont de quantification `p_i=t+h·q_i` ; profils u16/binary64 à statuts distincts.
8. La méthodologie de mesure : pentes par comparaison entière `m2^q n1^p <= m1^q n2^p` (`RampSlopeAnalyzer-v1`), règle d'arrêt deux exposants `>1,35`, `eight_clusters` comme famille qui décide, différences appariées baseline/combined sur le même univers.

**Éviter absolument :**
1. Toute expansion `arête × porteur × apex` avant le rang ; tout tableau/allocation indexé par un univers de cofaces ; toute Delaunay.
2. Toute cascade d'arité (verdicts, records, caps ou provenance partagés entre lanes — le vecteur `acu` partagé de la sonde J0 est le contre-exemple).
3. Les compteurs comme sources, les accords de cardinalité comme preuves (comparer les **records complets** : `SupportKey`, owner, `I_B/U_B`, `BallKey`), les juges partageant les primitives du sujet, les oracles silencieusement sautés.
4. Les coupures empiriques auto-certifiées (`0,75·dmax`), les quadratures sans intervalle, la censure des éléments lourds dans une moyenne, l'addition de ledgers de deux vues.
5. Promouvoir un certificat ponctuel/paire au rectangle sans preuve uniforme (`JungDiskDepth`), ou un `ALL` de coins sur un bloc à support variable ; confondre `ALL` et `NONE` (coins extérieurs ≠ `NONE`) ; `max H<=0` vs `<0` (shell).
6. Dimensionner des buffers sur la position générale (384 cocycliques ⇒ 2,3 M supports d'une sphère) ; jitter ; toute égalité doit descendre ou refuser.
7. Choisir la politique par nom de famille de nuage ; décider une rentabilité transitive avant d'avoir mesuré l'aval ; lancer une rampe G4 avant portes CPU vertes.

## Questions ouvertes / ambiguïtés

1. **Choix de `η` (niveau de cellule carrier)** : aucun argument n'impose `η=Θ(1/s)` ; la rentabilité du compromis `s³η⁻³`/`s³η⁻⁶` reste à mesurer. Directement pertinent pour le choix `s=6/8/10` de la V4.
2. **`k_t ~ n^0,25`** (Q7 de Claude, sans réponse dans cette tranche) : croissance intrinsèque de la lentille ou artefact de l'arrêt sur nœuds LBVH au lieu de cellules Morton de niveau fixe ? Le voisinage de `(2·sqrt(3))³=41,6` n'est pas reçu.
3. **`2B_R` vs lentille exacte** (Q8) : lequel domine en nombre de cellules ? Non tranché ici.
4. **Gate contre les mutants sur-couvrants** (Q9 : `wst3-pas-de-descente` survit) : plafond blocs/rectangle ou comparaison appariée ? Non tranché.
5. **Juge de la profondeur `d` niveaux 0..7** (Q11) : l'arrangement complet des demi-plans dans le disque, en BigInt à petit `n`, est proposé comme autorité mais la réponse n'est pas dans cette tranche.
6. **Granularité vs seuil** (Q9 de 6 quater) : `need=8` à `smax=11` tombe au milieu de la distribution des témoins — question de spécification jamais tranchée explicitement.
7. **`TetraDepthBlock`/`BlockBallDepth8`** : proposés, contre-audités comme spécification, mais **jamais implémentés ni mesurés** dans cette tranche ; deux pentes physiques rouges les réfuteraient. La V4 en hérite comme pari central non validé.
8. **WST4 symbolique vs sweep par face** : le choix physique (A vs B) est explicitement reporté « après les gates physiques de WST4 » — jamais exécuté.
9. **Statut du secondaire `K=5 / <1 s`** : le facteur 12 théorique (`240/20`) est contredit par le repli mesuré `5,35×` (`smax=11→6` sur les candidats) ; les deux nombres ne mesurent pas le même objet (masse de sortie vs candidats), l'écart n'est pas expliqué.
10. **binary64** : le profil séparé (décodage dyadique exact, filtres GPU unilatéraux, fallback multiprécision) est décidé dans son principe mais aucune largeur de bits n'est établie hors u16 — toutes les bornes i128/i192 sont à refaire pour la V4 si l'entrée n'est pas `t+h·q_i`.
11. **`E_e` par paires de cellules** (identité factorisée M4) : spécifié par l'auditeur, jamais implémenté ; microgates listées mais non écrites.
12. **Fixture manquante signalée** : `OUVERT+apex_retenu_deep` (protection de la branche de reconstruction du replay) ; et la canonisation de la priorité des fates (`PENDING_CAP` vs `UNSUPPORTED_DEGENERACY`) reste ouverte.
13. **Contradiction apparente sur le coût SOC** : « 4 à 6 couples de coins par tâche » (Claude) vs `+75 %` de temps de vague mesuré par l'auditeur — explicitement non tranchée (« personne ne le peut encore »), suspendue à la mesure de l'aval.
