Périmètre : les 26 fichiers demandés de `morsehgp3D_v3/` (tous présents ; les `.hpp` et le README lus intégralement, les probes volumineux lus par en-tête + structure + portes). ## Conventions transverses (valables pour tous les fichiers)

- **Profil u16 uniquement** : coordonnées entières dans `[0, 65535]`. Aucune position générale supposée ; toute dégénérescence (points confondus, support affinement dépendant `den == 0`) produit un **refus explicite, jamais un jitter**.
- **Codes de sortie normalisés** (via `mhgp3v_add_expected_code_test_for`, `cmake/expect_failure.cmake`) : `1` = désaccord du juge ; `2` = campagne refusée AVANT calcul (CLI invalide, domaine non fermé) ; `3` = plancher/invariant violé (aussi budget/NO-GO dans `pair_selfjoin`/`pair_anchor`, qui utilisent `1` pour identité/soundness) ; `4` = mutant tué. Les crashs par signal sont refusés partout.
- **Planchers `--min-*`** contre le vert-par-vacuité (ex. `--min-closed`, `--min-carrier`, `--min-region-prunes`, `--min-jamais-proposes`, `--min-soc-taches`…), **fixtures gravées** aux coordonnées exactes, **mutants `--inject=`** modélisant chacun une faute réellement écrite, **équivariance** par permutation / threads / politique.
- **Juges à arithmétique volontairement différente** du sujet (i128 vs BigInt, forme `‖2x−u−v‖²−‖u−v‖²` vs forme produit, rationnels signe-magnitude vs Cramer entier) ; les CTest `PASS_REGULAR_EXPRESSION` sont doublés d'une porte à code de sortie.
- Vocabulaire : **fail-open** (un certificat qui échoue ne conclut rien, jamais `NONE` ni `SOURCE_EMPTY`) vs **fail-closed** (un codec qui doute refuse) ; **counter-only** (mesure, aucun fate touché) ; un dépassement de **budget rend une continuation, jamais un verdict**.
- Prédicats géométriques : **entiers exacts partout** (i64 → i128 → `BigInt<4>` 256 bits selon largeurs prouvées en tête de fichier). Les seuls flottants rencontrés : `std::sqrt(double)` comme *graine* d'`isqrt` corrigée dans les deux sens (`rect_isqrt_floor/ceil`), les émases de mesure (`double rad` de `rect_front_probe` sert d'heuristique de priorité, jamais de décision), et les pentes/`log2` des portes d'échelle.

## 3. `wspd_front.hpp` (98 l.) — prédicats de séparation entiers

Rôle : la séparation WSPD **sans aucun flottant**, construite avant toute géométrie ; « un rectangle séparé mais non fermé est simplement transmis » (la WSPD ne décide aucune géométrie scientifique).

- **Forme L∞ entière, quantités doublées** : `c2_i = lo_i + hi_i`, `r2 = max_i (hi_i − lo_i)`, `d2 = max_i |c2A_i − c2B_i|` ; arrêt exact à `s` entier : `d2 ≥ r2A + r2B` **et** `d2 − r2A − r2B ≥ s·max(r2A, r2B)`. Tout tient en i64 sous u16.
- **Forme euclidienne en carrés** (`wspd_separated_euclid`, `s = p/q` rationnel) : avec `W2 = Σ w_i²` (diamètre carré) et `D2 = Σ (c2A_i − c2B_i)²`, le test est `q²·D2 ≥ (p+2q)²·max(W2_A, W2_B)` (produit final en `__int128`). C'est une **implication** (`r_A + r_B ≤ 2·max`) : peut **perdre** des séparations quand les rayons diffèrent, jamais en **inventer**. Bornes : `D2 ≤ 3×131070² < 5,2e10`, membre droit `< 2^47` pour `p/q ≤ 32`. Motivation documentée : la variante L∞ annonçait un `s` jusqu'à `√3` fois plus faible en euclidien que déclaré (langue des certificats).

## 4. `wspd_front_probe.cpp` (611 l.) — `WspdFrontLowerBound-v1`

Partition CK sur un **arbre à découpe équitable** (axe le plus large, coupe au milieu de la boîte, tie-break final par `PointId`, `stable_sort` → identité du rectangle indépendante de l'ordre d'entrée), **refus `leaf != 1`** (les self-blocs feuille > 1 ne sont pas développés — domaine fermé avant calcul, directive `90aa941`), refus des positions coïncidentes. Récursion croisée : split du côté au plus grand rayon.

- **Passe 1** : partition seule (diagonal `(v,v) → (L,L),(R,R),(L,R)`), aucune géométrie. **Passe 2** : une classification par `RectId` terminal, **masque de lanes commun** (bits q2/q3/q4) : descente best-first sur les nœuds témoins, priorité `−Vhi` (le plus « central » d'abord), crédits saturés à `kNeed = {10, 9, 8}`, quantum d'évaluations par rectangle (invariant `over_quantum == 0`, code 3).
- **Oracle d'identité** (n ≤ 64) : développer tous les records et exiger **domaine** (aucune clé diagonale/hors domaine), **cardinal** (`C(n,2)` clés exactement), **multiplicité** (exactement un) — « la somme des masses ne prouve rien : une omission et un doublon de même masse se compensent ». Mutants `--inject=omission` / `--inject=doublon` au 7e record. Digest FNV des clés pour l'invariance par permutation. Identités persistantes : clé de nœud = condensat (époque, `PointId` triés) ; `RectId` = condensat (époque, deux clés ordonnées) — jamais le chemin de split.
- Banque Morton bornée **strictement propositionnelle** (`--bank`, fenêtre `W`, sélection `L` plus proches du centre `m4/4`, rejet des endpoints, dédoublonnage borné à 64) : propose des `PointId`, chaque ID **recertifié** sur tout `A×B` par le masque central `Dlo/Vhi` ; perte de rappel Morton **admise**, jamais une faute. `--carriers` : `SOURCE_EMPTY` q3 seulement après partition **exhaustive** du domaine témoin en nœuds `NONE-porteur` ; budget épuisé → `UNKNOWN`.
- Porte de pente : refus (code 3) si **deux pentes consécutives** de `front_records ≥ max_slope` (défaut 1,35).

## 5. `wspd_wavefront.hpp` (175 l.) — WSPD par vagues sur octree Morton

Transcription CPU du kernel GPU visé. Trois idées :
1. **Arbre radix de Karras** sur clés Morton 48 bits (`wf_spread3` pas TROIS, masque `0x1249…` ; l'ancien masque `0x5555…` du pas DEUX était une faute corrigée) : `n−1` nœuds internes, un thread chacun, aucune récursion. **Précision corrigée** : l'arbre binaire n'est pas un octree compressé mais son **déroulé binaire** — seuls les préfixes multiples de 3 donnent des cubes, les autres nœuds ont un rapport d'aspect 2 ou 4 ; la borne CK `O(n log n + s^d n)` tient à une **constante** près (au pire `8^d`), jamais une pente.
2. **Cas diagonal déroulé** : `WSPD(v,v)` devient « pour chaque nœud interne, émettre la graine `(gauche, droite)` » — un seul kernel plat, la récursion diagonale disparaît.
3. **Vagues `count → scan → fill`** : chaque paire active rend 1 (séparée, terminale) ou 2 (scindée) ; profondeur ≤ `2·log2 n`, travail ≈ 2× la sortie.

`WfNode` : `left/right` (`<0` = feuille `−1−index`), plage `[first,last]`, `level` (côté cellule `2^(16−level)`), **cellule Morton alignée** `lo/hi` ET **boîte serrée** `tlo/thi` (remontée post-ordre `wf_tight_boxes`, sur GPU = propagation ascendante LBVH à compteur atomique). **Séparation sur la cellule, certificats sur la boîte serrée** — mesuré : la cellule seule multiplie le front par ~6,5.

## 7. `pair_frame.hpp` (662 l.) — l'ABI du tronc commun q2/q3/q4

Le fichier le plus directement réutilisable comme **spécification d'état GPU** pour la V4.

- `PairFrame { rect_id, a_node, b_node, pair_mass:u64 }` : le tronc commun **sans aucun fate de lane** ; trois états `Lane2State/Lane3State/Lane4State` ne partagent QUE lui (autonomie des producteurs ; une fermeture q4 ne doit jamais annuler du travail q3, fuseaux emboîtés `W4 ⊂ W3 ⊂ W2` ; un kernel peut évaluer les trois prédicats en une passe mais écrit dans trois états).
- `CoreFate` : `kMixedCore / kPrunedUniversal (lower ≥ h_q) / kCoreClear (upper < h_q) / kExactify / kPendingResource` — `kCoreClear` n'est PAS « vivante exactement » pour q3/q4 (le census de la vraie circumboule reste dû) ; `kPendingResource` n'est JAMAIS un verdict.
- `CoreDepthLedger` : `reject_threshold = h_q = s_max − q + 1` (u8), `lower_open_sat = min(h_q, lower)` (u8), `frontier_candidate_mass_exact` (u32, **la masse est exacte, le majorant est dérivé** : `upper = min(h_q, lower + masse)` — jamais stocké saturé, cf. mutant `kUpperSatureIncr` : majorant vrai `100→95`, stocké `10→5<h` ⇒ faux `CORE_CLEAR`, **faute de sûreté** § 3.3), `frontier_width` scalaire (jamais `size()` — `O(F)` déguisé en `O(1)`), `frontier` / `relation_frontier` (spans endpoint : jamais crédités, mais **conservés et rejoués** après restriction de `A`/`B` — P0.1 de `79e73b6`).
- **La saturation est un théorème** : la décision ne dépend de `(lower, upper)` que par `(min(h,lower), min(h,upper))` → deux octets transportables en registre GPU (porte `mhgp3v_pairframe_saturation`, couples jusqu'à `10^9`).
- **Deux caps, deux ressources** : `exact_tile_cap` borne `pair_mass × frontier_candidate_mass_exact` (**évaluations ponctuelles** — le P0 de `08b7007` : un cap sur `pair_mass × frontier_width` sous-compte d'un facteur égal à la population du span, jusqu'à 50 000) ; `frontier_cap` borne les handles résidents (`kCapRacines` d'un CTA, défaut 64). Comparaison par **division** (`tuile_tient`), jamais par produit. Avec cap sur masse seule, `kPending` est **inatteignable** (preuve en une ligne : endpoint non scindable ⇒ deux feuilles ⇒ `pair_mass = 1`) — trouvé par un plancher, pas par relecture.
- Actions : `kTerminal / kExactifyTile / kSplitWitness / kSplitOneEndpoint (une fois par paire) / kPending` ; `witness_batch` `B` (`0` = tous) avec `lot_effectif` bornant par le budget restant (P1 : `budget=1, batch=8` produisait un budget négatif ; le batch d'antichaîne est mathématiquement sûr, le contrat de ressource ne l'était pas).
- `CoreContinuation` **typée** : antichaîne complète (`decided_spans` portent le minorant, `mixed_spans`, `relation_spans`), `policy_version` **hors sémantique** (porte `reprise_politique_croisee` : mêmes identités sous une autre politique).
- **Codec fail-closed** : magic `"PFC1"` (0x50464331), schéma 1, en-tête 44 octets, CRC32 sans table ; `DecodeError` à 15 codes ; **préflight complet avant toute allocation** (cardinalités `na/nm/nr` contre les octets restants), puis sémantique : domaine des handles, antichaîne (aucun doublon, aucune relation ancêtre), masse recalculée == stockée, seuil, époque, résidu.
- **Bug suspect** (l. 600–603) : la validation de domaine des endpoints teste `k.a_node >= dom_ep` mais `k.b_node > dom_ep` — un `b_node == dom_ep` (hors domaine par un) passe le décodage. Off-by-one non couvert par un mutant visible.
- Mutants ABI : `kSatureTronque` (tronque à 8 bits — meurt dès `lower ≥ 256`), `kClearLarge` (`≤` : faute de sûreté), `kPrunedLarge` (`>` : conservateur mais ne **termine** plus), `kPendingPruned` (« le péché capital »), `kCapAvantVerdict` (conservateur, tué au plafond de travail — dit honnêtement), `kCoutTuileLargeur`.

## 10. `pair_selfjoin_probe.cpp` (1 059 l.) — self-join q2 mass-only

Grille uniforme CSR (`start`/`item`, comptage-préfixe), **offsets triés par distance minorante conservatrice** (`ax = max(0, |x|−1)` par axe, `offd2 = (ax²+ay²+az²)·cell²`) : une requête `query(ctr, r, f)` s'arrête dès `offd2 > r²` — ne paie que les premières couronnes ; le callback peut abandonner (`return false`). ## 23. `prefix_index.hpp` (190 l.)

**Théorème** : sous un ordre total **commun et immuable** sur les PointId, avec `P_k(S)` = les `|S|−k+1` premiers éléments, `|M∩N| ≥ k ⇒ P_k(M) ∩ P_k(N) ≠ ∅` — filtre sans perte, recertification exacte ensuite (`prefix_recertify`, sortie anticipée). Longueur optimale au pire cas (mutant `prefix-length-minus-one`). **Possession canonique** (audit `8df7ac8` P0) : lot stagé entier avant la première requête ; une paire Q–Q possédée exactement une fois par l'`ActivationId` le plus grand (= position d'activation dans l'ordre global, **jamais** un numéro de racine DSU). **Préflight exact** : `H_Q = Σ_x q_x·d_x`, degrés figés à la clôture du staging ; `predicted_hits == hits` est un **invariant à refus**. Neuf mutants (dont `order-per-query` — un ordre par requête invalide le théorème —, `duplicate_posting` tué par l'identité de masse, `double_query_pair`, `future_visible`, `stage_query_sequentially`). Statut : conservé uniquement parce que `saturated_fold_hybrid.hpp` en a besoin ; « le préfixe comme autorité exhaustive » est une piste **interdite** par le registre racine.

## 24. `cloud_families.hpp` (404 l.) — les familles de mesure et les contre-familles

Toute construction **entière** (aucune libm sur le chemin des points ; reproduction inter-hôtes exacte), déduplication par clé `(x<<34)|(y<<17)|z`, garde `200n` (ou `400n`).
- `uniform` : tirage entier dans `[0, coord)³`, densité volumique `1e-3`, `coord = cbrt(n·1000)` — **le régime le plus dur mesuré** (`I ~ n^1,6` sur 800..2400).
- `eight_clusters` : 8 amas aux sommets d'un cube, `coord = 4·cbrt(n·1000/8)`, demi-côté `coord/8`, tourniquet strict à quota `⌈n/8⌉` — attaque les certificats de témoins (milieu inter-amas dans le vide).
- `terrain` : densité aréale 1 pt / 25 cases (`coord = sqrt(25n)`), 6 calottes quadratiques entières `amp·(r²−d²)/r²`, jitter sol `{0,1,2}` (coplanarités massives assumées), 2 % de canopée.
- `scanline_single_pass` (`coord = sqrt(40n)`) : pas 2 le long de la ligne / 8 entre lignes (anisotropie 4:1), une ligne sur trois au pas double, trous markoviens (entrée 1/40, sortie 1/8 ≈ 1/6 du linéaire perdu), plateaux rectangulaires à **bord franc**, jitter `{0,1,2}`.
- `scanline_overlap_multiecho` : deux passes faiblement décalées + multi-échos verticaux (jusqu'à 3 retours). **Contrat de cardinalité** : chaque `push` borné par `n` (l'ancienne garde par pixel laissait passer 12 501 points pour 12 500 à coord 707 et désynchronisait ledger/fate/oracle ; `mutant_overshoot` rétablit la faute pour la porte).
- `two_lines` (**réfutation gravée, déterministe**) : `A_i = (i,0,0)`, `B_j = (0,j,H)`, `H = coord−1`, indices dès 1. Chaque paire croisée a une sphère **vide** de centre `(i, j, (H²+i²−j²)/(2H))` (puissances `(k−i)²`, `(l−j)²` > 0) ⇒ **aucun certificat universel sound** (masque central, SOC64, CORNER512, LP, cages) ne ferme ces `n²/4` paires ; et pourtant la vraie source q3/q4 y est **vide** (`(A_k−A_i)·(B_j−A_i) = −(k−i)·i < 0` : aucun triangle aigu). `coord = 65536` exigé.
- `collinear_seven` (**seconde réfutation** : le crédit de groupe ne s'ajoute pas) : `a=(0,0,0)`, `b=(10,0,0)`, `z_i=(i,0,0)`, i=1..7 ; pour tout centre `(5,u,v)` la marge à `z_i` vaut exactement `i(10−i) > 0` : **profondeur exactement SEPT**, le seuil q4 en demande huit — un crédit de groupe sans vérification de disjonction publierait un huitième crédit sans huitième identité.

## 25. `emst_boruvka.hpp` (327 l.) — la lane k=1 (EMST exact = single linkage)

Borůvka sur le `MortonLbvh` partagé (le cœur le **consomme**). Aucun flottant publié : `levels4 = 4·niveau = d²` exact en i64 (`d² ≤ 3·65535² < 3·2^32`). Par ronde : (1) étiquettes DSU ; (2) **pureté par nœud recalculée en O(nœuds)** bottom-up (indices décroissants — l'ordre de construction pousse père avant fils) ; (3) requêtes best-first par point : élagage **STRICT** (`bd > best` seulement — un nœud pouvant contenir un ex aequo n'est jamais élagué : le canonique reste décidable), saut des sous-arbres purs de la même composante ; (4) départage **déterministe** des ex aequo par la paire canonique `(d², min id, max id)` — sortie rejouable, indépendante de la forme de l'arbre (replay multi-tailles de feuilles) ; (5) fusions **en fin de ronde**, dédupliquées par le DSU ; **ronde stérile = refus fermé**, jamais une boucle infinie. Compteurs de faisabilité : `rounds`, `node_visits`, `distance_tests`, `stack_high_water`. Cinq mutants : `reconnect_wrong_components` (mêmes niveaux, mauvaises composantes — la partition du juge diverge), `level_off_by_one`, `skip_last_round`, `purity_stale` (note de conception : la staleness temporelle littérale est prouvablement fail-slow-mais-correcte dans ce design — le mutant réalise l'effet par la voie qui mord), `tie_nondeterministic`. Le DSU du juge est réécrit à part.

## Synthèse — ce qui doit survivre en V4 (idées, pas code)

**Algorithmique.**
1. **La séparation WSPD entière** : la forme euclidienne rationnelle `q²D2 ≥ (p+2q)²·max(W2_A, W2_B)` (fail-open, i64/i128, aucune racine) — indispensable puisque la feuille de route V4 fixe `s = 6/8/10` et que les certificats sont euclidiens ; la forme L∞ ne parle pas la même langue (facteur `√3`). Séparation décidée sur la **cellule** (borne), certificats sur la **boîte serrée** (front ÷6,5).
2. **La construction par vagues** : Karras sur Morton 48 bits, diagonale déroulée en `n−1` graines, `count→scan→fill`, profondeur ≤ `2 log2 n` — plus l'astuce `--climb` (feuille de `m_0` puis remontée par frères : −42,7 % de descente pure).
3. **La disposition unique** `(Morton48, PointId)` + LBVH exact avec dominance composante-par-composante (ownership des colocalisés total et rejouable) partagée par toutes les lanes.
4. **L'algèbre exacte de rectangle** de `rect_front.hpp` : intervalle de H sur le réseau entier (sommet écrêté, vrai plancher pour sommes négatives), masque central `V2/D2` à trois seuils imbriqués (`1`, `1/3`, `56/209`) calculé une fois pour trois lanes, NONE de lane `c'U² ≤ LE·LX`, score-intervalle `rect_s_interval` qui donne enfin un NONE au certificat central, cœur étroit `(d−3S)/4` universel aux trois lanes.
5. **SOC64/Corner512** : les arguments de convexité (produit relaxé suffisant, enveloppe continue exacte), les largeurs prouvées (i128 suffit à tout), le contrat `floor`/`kUnknownBelowFloor`, et **corner64** (témoin ponctuel) adopté au cœur (`−38/−46 %` de résiduel q4 pour `+18 %` de temps) — directement le certificat « h témoins dans la zone cœur » de la V4.
6. **Le préfiltre combiné `h_coeur + h_a + h_b`** avec disjonction **prouvée** (un `z ∈ A` donne `H = 0`), décision par histogramme jamais par paire, coût `O(|A|+|B|)` — exactement l'architecture V4 ; le point à résoudre est le coût des auto-jointures `O(|A|²+|B|²)` : le dual-tree est reçu comme transformation sémantique correcte mais pas encore comme gain ; le patron qui **marche** est la traversée duale Q–W de Yao48 (héritage exact des deux verdicts, frontière persistante append-only, élagage exact quand `masse atteignable < K`).
7. **Yao48 pour q2** : banque de ONZE / dix engagés / D recalculé, coupe stricte à trois inégalités télescopiques, reçus de région et enveloppe radiale `dist² > 3·max D_c`, banques par antichaîne (n'importe quels dix témoins à `dist² ≤ D`), voie liste par préfixe trié — et les leçons de politique de travail (phase A budgétée + phase B dirigée par cône ; ~21 chambres remplissables/ancre sur terrain).
8. **Le cœur de Jung pour q3/q4** (`pair_anchor_probe`) : disque médiateur `D²/12`, `D²/8` ; prédicats `3g² > 4Q` / `g² > 2Q` ; seuils 9/8 ; théorème de couverture par l'arête diamétrale canonique ; le pré-prune large q4 `15‖U‖² ≤ 4D²` licite. Et son **complément indispensable** : les porteurs (`M0 > 0` strict, `H < 0`) vivent dans la région **complémentaire** des témoins — la V4 (troisième témoin x formant un triangle aigu) a besoin des deux moitiés ; `two_lines` prouve qu'aucun certificat universel seul ne suffit (`n²/4` paires infermables, source vraie vide).
9. **L'ABI d'état saturé** de `pair_frame.hpp` : saturation-théorème (2 octets), masse exacte / majorant dérivé, deux caps (évaluations vs handles), continuation typée fail-closed, batch d'antichaîne — la meilleure base pour l'« identification exacte et GPU-friendly des événements » de la V4.
10. **L'EMST Borůvka** exact sur LBVH (élagage strict, ties canoniques, pureté par ronde, fusions fin de ronde) pour la lane k=1 de la reconstruction de forêt.
11. **L'autonomie des lanes** : le rang n'est pas héréditaire (fixture 64 points q4 rang 4 / arêtes rang 12) ; fuseaux emboîtés mais états séparés ; une passe de calcul, trois écritures.

**Invariants de test.**
- Codes 1/2/3/4 systématiques + refus **avant** calcul des domaines non fermés ; portes doublées (regex + code).

- Planchers `--min-*` contre le vert-par-vacuité, y compris `--min-jamais-proposes` (l'incomplétude d'une fenêtre est mesurée) et les compteurs « branche exercée » (`emitted_positive_depth`, `dictionary_refuted == 0`, `static_assert` sur `absorb`).

- Fixtures gravées déterministes : `two_lines`, `collinear_seven`, la fixture d'égalité `4R² = delta²`, tie-lattice EMST, la contre-fixture SOC64 sous seuil.
- Invariance par permutation, par shards/threads (reçus égaux champ par champ), par politique (mêmes identités, seul le travail change) ; chronos en médiane/p95.

## Questions ouvertes / ambiguïtés

1. **`corner64_all_lane` introuvable dans `soc64_rect.hpp`** : le README le décrit comme « `soc64_rect.hpp::corner512_all_lane` privé de ses huit coins de témoin confondus », mais le fichier lu ne définit que `soc64_all_lane`, `corner512_all_lane`, `scalar_extrema_all_lane`, `exhaustive_all_lane`. Il vit probablement dans `combined_prefilter_probe.cpp` (non demandé) — à vérifier avant de citer sa signature.
2. **Off-by-one suspect dans `decode_continuation`** (`pair_frame.hpp` l. 600–603) : `a_node` validé par `>= dom_ep`, `b_node` par `> dom_ep` — un `b_node == dom_ep` passe. Aucun mutant ne semble le couvrir ; intent non documenté.
3. **Budgets Yao48 divergents** : `bank_pop_budget = 4096` par défaut dans le header, `bank_pops = 512` par défaut dans le probe. Lequel est le réglage « mesuré » de référence n'est pas dit dans les fichiers lus.
4. **Paramétrisations q3/q4 multiples** : `3H² > E2X2` (soc64, q4) ≡ `2H² > Xi` (README, `Xi = R = E2X2 − H²`) ≡ `g² > 2Q` (pair_anchor, variables `g, Q` du plan médiateur). Elles sont cohérentes mais non unifiées ; la V4 devrait fixer UNE forme canonique et dériver les autres, sous peine de confondre les constantes (le mutant `swap-coeff` 3↔4 existe précisément pour ça).
5. **`h_q` : deux écritures** — `pair_frame.hpp` dit `h_q = s_max − q + 1`, le wavefront probe calcule `smax + 1 − q` (identiques) ; mais `s_max = 11` (K=10, `p+q ≥ 12 = K+2`) est implicite dans les constantes 10/9/8 : la relation contractuelle `s_max = K + 1` n'est écrite nulle part dans les fichiers lus.
6. **`window_source` et arêtes maximales** : le certificat de fenêtre couvre le shell global mais dépend d'un k-NN exact (`delta_out`) dont le producteur n'est pas dans ce lot ; la manière dont V4 obtiendrait `delta_out` à des dizaines de millions de points (et si la « recherche de l'arête maximale via WSPD » de la feuille de route la remplace) reste un choix de conception ouvert.
7. **Chiffres de fermeture de la dominance 432** : le README les qualifie lui-même de « diagnostic counter-only, sans reçu épinglé ni pente à trois points » — ils justifient la réouverture, pas une adoption ; leur croissance avec n (seul certificat du dossier à croître) mérite une mesure à 8000/16000/32000 avant tout engagement V4.
8. **`wf_cell` / arbre de Karras et clés dupliquées** : `wf_delta` gère les clés égales par `64 + clz(i^j)`, mais les probes **refusent** les positions coïncidentes en amont ; le comportement de l'arbre par vagues avec colocalisés (que le profil V4 « dizaines de millions de points » rencontrera, cf. multi-échos) n'est validé nulle part dans ce lot — le `MortonLbvh` récursif, lui, a le fallback midpoint et l'ownership `(clé, PointId)`.
