## Ce que les tours 9–10 ont effectivement fermé

### Enveloppe temporelle

`scp_worst_case_s(1)` et `POST_BUDGET_S` comptent maintenant le même chemin :
SCP, grâce, backoff, deux describes et deux réserves d'arrêt. La fixture à une
seconde tue l'ancien coefficient 1.

Avec les valeurs G4 par défaut :

- budget post-campagne : 2 915 s ;
- fenêtre G4 : 24 295 s pour une estimation déclarée de 23 794 s ;
- marge nominale sur cette estimation : 501 s ;
- `cutoff - deadline = POST_BUDGET_S + 90 s`.

Le hard-kill maximal de campagne laisse encore `POST_BUDGET_S + 30 s`, puis
la garde SCP relit l'heure et refuse tout chemin dont le pire cas ne tient
plus. Les contrôles de génération post-handshake, post-bundle et
pré-campagne sont en outre clampés avant leur describe.

### Arrêt ciblé

Sur une sortie pré-SCP, un premier échec transitoire provoque une seconde
tentative : le second arrêt réussit, aucun SSH/SCP/validateur n'est lancé et
le reçu conserve la cause initiale `rc=77` avec `stop_rc=0`. Un échec
persistant effectue exactement deux appels puis termine en blocage 70.

Si la garde a déjà enregistré `targeted_stop_failed`, le cleanup ne fait
qu'une reprise : la borne globale reste donc deux appels. Après
rapatriement, le ledger démontre `STOP1 < STOP2 < VALIDATE`; un double échec
d'arrêt interdit la validation et tout troisième appel.

### Instrumentation et décision

Le lifecycle transmet explicitement `TIME_BIN=/usr/bin/time` à la commande
distante. Le validateur exige un champ `time_bin` unique, non vide et
présent pour chaque run annoncé.

Les témoins appariés ferment les branches utiles :

- `decision_v1 + /usr/bin/time` atteint `decision_complete` ;
- `decision_v1 + faux TIME_BIN` est déclassé ;
- `g4_mesure_v1 + faux TIME_BIN` est invalide, code 1 ;
- un champ `time_bin=` vide est refusé.

Un code antérieur, notamment 77, n'est plus écrasé par le code 65 du
validateur.

## Limite résiduelle correctement bornée

Le validateur écrit actuellement les fichiers `*_resume.txt` avant son
contrôle final de l'instrumentation G4. Un faux instrument de test peut donc
laisser physiquement des résumés, puis rendre le code 1. La réponse Claude
disait littéralement que ces RSS n'étaient « jamais dans les résumés » :
ce claim fort n'est pas reçu.

Cette limite ne bloque pas la session autorisée ici :

- le seul chemin autorisé impose `/usr/bin/time` ;
- un résultat n'est recevable que si le validateur termine avec le code 0 ;
- tout résumé issu d'un code non nul est un artefact diagnostique invalide,
  jamais une mesure consommable.

Déplacer la vérification avant l'écriture des résumés, ou publier ceux-ci dans
un espace explicitement `invalid`, serait un petit durcissement P1 utile. Il
ne justifie ni un nouveau veto ni une autre boucle d'audit avant l'essai
gardé.
