## P0-2 — l'entrée authentifiée documentée est inexécutable

Le commentaire de `session_campagne_v6_g4.sh:10-14` propose :

```bash
C=$(git rev-parse HEAD)
git show "$C:gcp-migration/session_campagne_v6_g4.sh" > /tmp/boot.sh
MHGP6_BOOTSTRAP_COMMIT="$C" bash /tmp/boot.sh
```

Mais l'étage 1 calcule sa racine depuis `$0` :

```bash
REPO_ROOT="$(cd "$(dirname "$0")/.." && pwd)"
```

Pour `/tmp/boot.sh`, cette racine vaut `/`. Le script fait ensuite `cd /`,
puis ses deux `git show` échouent hors dépôt. L'entrée qui devait éviter le
worktree est donc morte.

L'invocation normale ne remplace pas cette garantie : avant de comparer son
SHA à la copie du commit, le fichier du worktree a déjà été interprété par le
shell et pourrait neutraliser tout le protocole. Les tests « pin altéré » et
« bootstrap altéré » sont utiles, mais n'exécutent pas la commande externe
exacte annoncée.

Correctif minimal :

1. capturer à l'extérieur une racine absolue avec
   `git rev-parse --show-toplevel` et la passer dans
   `MHGP6_BOOTSTRAP_REPO_ROOT` avec le commit ;
2. faire privilégier puis valider cette racine par l'étage 1 avant ses
   `git show` ;
3. graver un selftest de la commande documentée exacte depuis un fichier
   temporaire hors dépôt, qui atteint bien le pin matérialisé sans mutation
   GCP.

## P0-1 — sûreté de fermeture reçue

Le chemin courant satisfait désormais les propriétés de sûreté essentielles :

- le trap extérieur est installé avant la première mutation GCP ;
- `start_and_verify.sh` publie l'état conservatif avant l'appel de start,
  puis la génération par écriture atomique, `fsync` fichier et parent ;
- l'arrêt d'urgence interne publie `targeted_stopped` après certification ;
- le cleanup extérieur reconnaît ce terminal et n'effectue pas un second
  arrêt ;
- tout autre arrêt extérieur reste lié à la génération exacte ; une
  génération illisible après mutation attestée reste un blocage explicite.

Cette réception concerne la **sûreté de fermeture**. Elle ne transforme pas
encore l'état et le reçu en journal transactionnel complet : voir P1.

## P1 — état, configuration et reçu à terminer

### Terminal extérieur absent

Après un `stop_and_verify` extérieur réussi,
`v6_session_lifecycle.sh:239-245` ne republie pas `targeted_stopped`. Le reçu
est écrit avec `issue=arret_tente`, tandis que `etat_cycle_vie` reste souvent
`targeted_running`. L'arrêt réel est certifié, mais l'autorité durable raconte
encore un état non terminal. Publier atomiquement le terminal avant le reçu
et réserver `arret_tente` au cas non certifié.

### `CLOUDSDK_CONFIG` pas toujours privé

La copie privée n'est créée que si `CLOUDSDK_CONFIG` est vide **et** si le
dossier par défaut existe. Une valeur déjà fournie réutilise la configuration
du caller ; l'absence du dossier laisse aussi `gcloud config set project`
créer ou modifier la configuration par défaut. Toujours créer une cible dans
`WORK`, y copier la source sélectionnée si elle existe, puis exporter cette
cible avant toute commande `gcloud`.

### Reçu réutilisable et non atomique

Le chemin par défaut ne contient que la date et le commit. Deux sessions du
même jour au même pin collisionnent. `mkdir -p` et les copies écrasent alors
le reçu précédent ; un ancien `SHA256SUMS` entre même dans le nouveau glob de
hash avant d'être remplacé. Utiliser un identifiant de session unique, refuser
une cible existante ou symbolique, écrire dans un répertoire temporaire puis
publier par renommage atomique.

### Profil décisionnel encore surchargeable

`THREADS_VM` peut changer sans dégrader `EFFECTIVE_PROFILE` en `custom`.
`RUN_TIMEOUT` influence les runs mais n'est pas inscrit dans le profil remis
au validateur. Les planchers `V5_GATE_MIN` et `V6_GATE_MIN` peuvent être
abaissés par l'environnement sans déclassement. Pour `decision_v1`, épingler
tous les axes sémantiques et toutes les portes ; toute surcharge doit être
refusée ou classée `custom`, et le validateur ne doit jamais traduire
`profil=custom` en décision.

### Fenêtre SCP non liée atomiquement au boot

L'envoi du bundle est encadré par des contrôles de génération, mais il écrit
sur la VM et n'est pas lié au `boot_id` dans la même commande. Un redémarrage
entre le handshake et le SCP peut donc recevoir le fichier avant que le
contrôle suivant ne refuse l'attribution. Recevoir dans un temporaire puis le
promouvoir sous un test `boot_id` dans la même commande, ou transporter les
octets par une commande SSH gardée.

## Porte de réouverture

Une session facturable devient auditable lorsque :

1. l'entrée authentifiée hors worktree fonctionne et sa commande exacte est
   testée ;
2. l'arrêt extérieur publie son terminal avant un reçu unique et atomique ;
3. `CLOUDSDK_CONFIG` est toujours privé et le profil décisionnel couvre tous
   ses axes et planchers ;
4. la fenêtre d'envoi est liée au boot avant écriture ;
5. les trois selftests restent verts et un audit statique frais conclut GO.

GCP non utilisé par le présent audit.
