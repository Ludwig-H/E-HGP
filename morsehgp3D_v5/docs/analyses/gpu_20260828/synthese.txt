# Lane résidente sur device — conception (L7)

Pin de conception : `6576e44c` (conception initiale) + contre-expertise adverse du 28 août 2026 intégrée. Cadre annoncé : `phase=exploration_v5_hors_registre backend=cpu_reference profile=quantized_u16_input_only mode=audit_independant_math_and_architecture public_status=not_claimed`. Le device reste un **producteur subordonné** : l'objet est défini par la production hôte (`pipeline/generate.hpp`) ; le device doit lui être égal vecteur à vecteur après tri/RLE, jamais l'inverse. Tout désaccord cpu/gpu est un bug device jusqu'à contre-fixture hôte. Tous les chiffres de cette section sont des **budgets** ; la mention « à mesurer » est normative : rien de ce qui la porte n'entre dans un reçu avant sa mesure.

## 0. Décision

Le chemin device actuel (reçu 12, 50 k uniform, 48 exécuteurs `thread_local` synchrones sur un seul device) est **non viable par construction** : murs exécuteur cumulés q4 = H2D 27,4 s + attente K1 42,2 s + hôte 4,2 s pour un `kernel_ms` de 7,5 s contre une lane CPU de 3,0 s, covers copiés à 64 o/site (≈ 37 Go par lane). La décision est donc structurelle avant d'être un gain de mur :

1. **Un seul thread exécuteur** propriétaire du device, trois flux (H2D, calcul, D2H), double tampon pinned, deux lots en vol ; les 47 autres fils produisent les rectangles vivants et consomment les survivants.
2. **Index résident** (positions, arbre, boîtes, `pid`) : 40 o/point, jamais recopié.
3. **Cover jamais matérialisé côté hôte** et **paresseux côté device** : l'histogramme des 32 classes radiales est calculé sur les visites sans écriture ; seules les classes nécessaires (0..10 pour les tests d'ancre, préfixe radial pour les seeds, queue à la demande pour les seeds vivants et la profondeur) sont écrites.
4. **Aucune clé ni niveau sur device** : clé exacte, niveau réduit, RLE, prefiltre, census, fold, digest restent hôte (L7c ouvre le census device comme second étage, optionnel).
5. Le gain **certain** de L7a est la suppression des 27,4 s de bus et des 42,2 s d'attente ; le gain de mur à 50 k est borné par Amdahl (§ 7) et n'est pas l'objectif de L7a. L7b (q4) et l'échelle 10–30 M ne se jugent qu'après trois sondes isolées (§ 9, verrous d'entrée).

Ce qui ne change pas : aucun jitter, tout prédicat décidé en entier (DI128/U192 device, i128 hôte), filtre flottant certifié à repli exact, sorties bit-identiques après RLE, compteurs comparés par les portes, refus explicites fail-closed vers le **même corps hôte** (`scan_anchor_q3` / `process_anchor_q4`, `AnchorPretests::kAlreadyAppliedWithGrid`).

## 2. Layouts device

Tous les tableaux sont indexés par `GeometryIndex` `u` (position unique, ordre Morton, `< 2^31`, audit G1), jamais par `PointId`.

```cpp
// gpu/resident_index.cuh — namespace mhgp5::gpu
struct PosD   { u16 x, y, z, pad; };              // 8 o, ushort4 coalescé, élargi en i64 à la lecture
struct NodeD  { i32 left, right, first, last; };  // 16 o ; feuille codée -1-u (convention NodeRef hôte)
struct BoxD   { u16 lo[3], hi[3]; };              // 12 o, boîte serrée ; feuille : box = pos[u]
struct ResidentIndex {
  const PosD* pos; const u32* pid; const NodeD* node; const BoxD* box;
  i32 m; i32 root;
};
```

Empreinte : 40 o/point → 50 k : 2 Mo ; 10 M : 400 Mo ; 30 M : 1,2 Go. `clo/chi/parent/wsum/keys` ne sont pas résidents. `pid[u]` plat exige des positions distinctes (précondition V1) : la famille `scanline_overlap_multiecho` doit soit passer V1 après bucketisation, soit être refusée **avant** la lane (V23).

```cpp
struct RectD       { i32 a, b; u8 need; u8 lane; u16 flags; i32 coef_num; };   // 16 o
struct AnchorD     { u32 rect; i32 ua, ub; u32 cost_class; };                   // 16 o, produite par K1
struct CoverSiteD  { i32 du, dv, dw; u32 u; u64 d2; };                          // 24 o (relatif à a, |p-a|^2, index)
struct CandD       { u32 ua, ub, ux, uy; };            // 16 o ; arité = 4 - nombre de sentinelles 0xFFFFFFFF
struct CandTaggedD { u32 rect; u16 seed_rank, lens_rank; CandD c; };  // 24 o, mode --raw-order-gate seulement
```

`CandTaggedD` porte le **rang du seed dans le cover radial** et le **rang dans la lentille**, pas seulement les identifiants : `(ux, uy)` sont des ids, ils ne restituent pas l'ordre hôte à un fil.

Contrats de lot (dimensionnement par contrat structurel comme `q3/q4_lane_batched.hpp`, lot scindé sinon) :

| Tampon | Contrat | Remarque |
|---|---|---|
| `rects` H2D | `2^18` × 16 o = 4 Mo | 2^20 était incohérent : 30–60 handles/rect dépassent `handles` ; 41 M ancres (eight_clusters) dépassent `anchors`. Les lots réels sont 2^17–2^18 rects : 4–8× plus de préflights que dans la conception initiale, à compter dans le recouvrement 3 flux |
| `handle_cnt` / `handle_off` / `anchor_cnt` / `anchor_off` | `2^18` × 4 o × 4 | 4 Mo |
| `handles` | ≤ `2^24` × 4 o | 64 Mo |
| `anchors` | ≤ `2^24` × 16 o | 256 Mo |
| arène cover | blocs en vol × 8 Mo | 188 × 8 Mo = 1,5 Go (350 k sites/bloc), voir § 6 |
| `cands` + compteur | `2^24` × 16 o | 256 Mo ; dépassement = lot refusé et rejoué scindé |
| compteurs u64 | 64 × 8 o | `GenerateStats` |
| **total device hors index** | | ≈ 2,1 Go par lot en vol × 2 |

Hôte : double tampon pinned pour `rects` et `cands` ; expansion `CandD` → `BallCandidate` avant RLE : **le pic mémoire hôte (6,2 Go à 50 k, 623 Go à 10 M en non tuilé) n'est pas réduit par L7** ; le candidat compact est un gain de bus, pas de mémoire (ECHELLE.md § 4.3 traite le pic).

## 3. Kernels

Constantes : `kCoverShared = 1024` sites (24 Ko), `kClasses = 32`, 256 fils par bloc, blocs persistants `grid = k × #SM` avec `k` **mesuré** par `cudaOccupancyMaxActiveBlocksPerMultiprocessor` au préflight, jamais déclaré. Budget de mémoire partagée par bloc ≤ 40 Ko (cover 24 Ko + seeds/lentille 4 Ko + grille 3 Ko + tampon d'émission 8 Ko + compteurs 1 Ko) : le plafond par SM en cc 12.0 est de **100 Ko** (99 Ko opt-in par bloc), pas 128 Ko ; 64 Ko/bloc donnait 1 bloc/SM et 12,5 % d'occupation. Cible 2 blocs/SM ; `__launch_bounds__(256, 2)` plafonne à 128 registres : les spills en mémoire locale sont **à mesurer** (`-Xptxas -v`, sonde § 9).

**K0 `k_rect_handles`** — warp par rectangle, pile de 64 `NodeRef` en smem par warp. Sur des clés Morton 48 bits distinctes la profondeur de l'arbre radix est ≤ 48 (préfixe strictement croissant), donc la pile est bornée par 49 : la garde 64 est **prouvable** (V21) et le chemin `kOverflowHost` de K0 est mort ; le mutant `overflow-drop` s'exerce donc sur l'arène et sur K1, pas sur K0. Reproduit `rect_cover_handles` : descente depuis la racine, gap² i64 contre `box_of(a)`, `box_of(b)`, coupe à ≤ 32 positions, ordre de pile identique (push left puis right, pop back). Deux passes : comptage → `cub::DeviceScan::ExclusiveSum` → remplissage, contrat vérifié `Σ cnt == off[last]` (refus du lot sinon, mutant `prefix-sum-off-by-one`).

**K1 `k_rect_anchors`** — bloc par rectangle. Le contrat est sur **`na² + nb² ≤ 2^17`**, pas sur `na · nb` : `corner_histograms` (`generate.hpp:196-211`) est quadratique en chaque côté ; un rectangle 10 k × 5 passerait l'ancien contrat et coûterait 10^8 `universal_over_corners`. Thread par (ia, iz) et par (ib, iz), histogrammes de coins en smem (`(na + nb) × 4 o`), `in_spindle_d` existant, ancres survivantes en ordre canonique (ua asc, ub asc) par prefix intra-bloc puis scan device. Au-delà du contrat : rectangle routé hôte. Classe de coût `cost_class = log2(Σ handle_points(rect))` (0..15).

**K2 `k_anchor_lane<L>`** — bloc persistant par ancre, file atomique sur `anchors` triée par classe de coût décroissante (`cub::DeviceRadixSort` stable : l'ordre intra-classe reste (rect, ua, ub)). Phases :

1. *Histogramme radial* (passe 1, sans écriture) : les 8 warps parcourent les handles en ordre canonique (handle k, puis `u` croissant, lecture coalescée de `pos[first..last]`) ; par visite : `d2q` en i64, test `d2q <= bound`, classe `bin` **sans division** : les 32 seuils `T_c = c (b+1)` (i64 < 2^45) sont précalculés par ancre en smem et `bin = #\lbrace c \in \lbrace 1,\dots,31 \rbrace : 32 d \ge T_c \rbrace` par recherche binaire à 5 comparaisons. Égalité avec l'hôte : $\lfloor 32 d / (b+1) \rfloor = \max \lbrace c \in \lbrace 0,\dots,31 \rbrace : c (b+1) \le 32 d \rbrace$, et $32 d < 2^{41}$ (car $d = \Vert 2z - (a+b) \Vert^2 < 3 \cdot 2^{34}$), donc u64 suffit ; la borne 2^39 de la conception initiale était fausse, sans conséquence. Comptes par classe en smem (sommes commutatives, déterministes).
2. *Cover paresseux* (passe 2, écriture) : seules les classes 0..10 et le préfixe radial jusqu'à `kCoverShared` sont matérialisés en smem ; la queue radiale est écrite dans l'arène du bloc **seulement si** un seed survit aux tests ou si une profondeur doit être calculée (phase 6). Le tri par comptage stable est fait **par rounds de 8 chunks de 32 sites** : passe 1 = histogramme global ; passe 2 = pour chaque round, `__ballot_sync(class == c)` donne les rangs intra-chunk, des curseurs de classe partagés avancent en ordre de chunk, barrière par round (13 rounds à 3200 sites, 1100 à 35 k). C'est le seul schéma qui reproduit la position hôte « offset de classe + nombre de sites de même classe avant lui dans l'ordre canonique » (`edge_cover.hpp:181-188`) ; un seul `__syncthreads` sur `smem_cnt[8][32]` ne le fait pas. Mutant `cover-sort-unstable` : visible **uniquement** sur les compteurs à sortie anticipée (le verdict est un compte), donc porte `counters_gate=strict` obligatoire, pas seulement le digest.
3. *Tests d'ancre* : W_q = compte de témoins par ballot + popc sur les classes 0..10 (ordre indifférent) ; secteurs : `bisector_basis` en DI128 par le warp 0 (boucle ≤ 128, à paralléliser sur les lanes si la sonde montre ≥ 1 % du temps K2 ; à 10 M, 3,4 G ancres × 4 k cycles ≈ 30 s device, non négligeable), puis 8 produits DI128 par site. Ancre morte : compteurs en smem, un `atomicAdd` u64 global par compteur et par bloc.
4. *Grille de cellules* (`cell_grid_wanted`, autorité unique `GenerateOptions::cell_grid_min_sites`) : Gram i64, `det` DI128, thread par site, deux pointeurs monotones, `cnt[16][16]` u32 en smem, `locate` en binary64 avec l'eps explicite de `cell_grid.hpp:259`. Le théorème d'eps suppose sept conversions correctement arrondies et une division IEEE : `-prec-div=true` et `-prec-sqrt=true` sont exigés, vérifiés à la compilation (`__CUDA_PREC_DIV__`) et la porte `grid` n'a de sens qu'**après** la porte `di_to_double`.
5. *Seeds* : `is_acute_seed` (i64), `seed_center_cell_dead` via la grille ; liste des seeds vivants en smem.
6. *Scan q3 / cœur q4* : warp par seed avec vol de travail intra-bloc, corps `q3_scan_seed_shaped` / `q4_seed_core_shaped` **inchangés**, SoA i64 lus depuis `CoverSiteD` ; affines du seed formées sur device par `seed_affine_d` avec `di_to_double_d` correctement arrondi.
7. *Complétions q4 et profondeur* (L7b) : lentille en smem si ≤ 2^16 paires (sinon hôte), `q4_completion_stage_shaped` existant, puis profondeur par ballot sur le cover ; la profondeur sur le cover complet est le poste dominant à 10 M (§ 7) : sa restriction aux classes radiales bornées est un verrou (V24) et non une hypothèse.
8. *Émission* : tampon smem de 512 `CandD`, un `atomicAdd(&cand_count, k)` par bloc, écriture coalescée.

```cpp
template <Lane L>
__global__ void __launch_bounds__(256, 2)
k_anchor_lane(ResidentIndex ix, const RectD* rects, const i32* handles, const u32* handle_off,
              const AnchorD* anchors, u32 n_anchor, u32* next_anchor,
              CoverSiteD* arena, u32 arena_sites_per_block, LaneOptionsD opt,
              CandD* cands, u32* cand_count, u32 cand_cap, u64* stats,
              u32* overflow_anchors, u32* overflow_count);
```

Lane q2 : même squelette réduit (`rect_diametral_candidates`, `kPretestQueryMinPoints = 512` conservé).

## 4. Ordonnancement et régimes

- File unique triée par classe de coût décroissante (LPT). La classe `log2(visites)` **ne modélise pas** le coût réel, qui est ≈ cover × seeds vivants (un seed q4 vivant occupe le bloc sur la lentille) : une ancre `cover = n` avec quelques centaines de seeds vivants en fin de lot est le mur du lot. La classe est déclarée **politique** ; la distribution du temps par bloc (`%smid`, `clock64`) est mesurée et un second critère (nombre de seeds aigus estimé par K1 sur les classes 0..10) est à évaluer, pas à promettre.
- Régimes par ancre : **S** (cover ≤ 1024 : tout en smem) ; **M** (1024 < cover ≤ 350 k : préfixe en smem, queue paresseuse en arène) ; **L** (cover > 350 k, ou `na² + nb² > 2^17`, ou lentille > 2^16 paires : hôte). Avec un cover moyen 35 k à 10 M et un seuil à 43 k, 20–40 % des ancres, les plus chères, auraient été routées hôte ; l'arène à 350 k sites/bloc (8 Mo) place le seuil à 10× la moyenne. La fraction L est **mesurée** (`routed_host`, en ancres et en sites) ; le banc n'est comparatif que sous le plancher V20.
- Deux lots en vol ; `cudaEvent` par lot ; jamais `cudaDeviceSynchronize` dans l'exécuteur.

## 5. Exactitude et déterminisme

**Prédicats existants réutilisés tels quels** (DI128/U192, `lanes/device_forms.hpp`, `gpu/*_shaped.hpp`) : `di_*`, `det3_d`, `q3_form_d`, `q3_power_d`, `q4_form_d`, `q4_power_d`, `q4_center_strictly_inside_d`, `in_spindle_d`, `is_acute_seed`, `anchor_owns_q3`, `q4_i64_prefilter`, `q4_face_power_prefilter`, `tetra_owned_by`, `q3_scan_seed_shaped`, `q4_seed_core_shaped`, `q4_completion_stage_shaped`, `q4_depth_shaped`, `cmp_2p2_jb2`.

**À écrire**, chacun avec fixture d'égalité hôte/device (≥ 10^7 tirages + cas gravés) :

| Prédicat | Contenu | Preuve exigée |
|---|---|---|
| `bin_of_d` | seuils précalculés + recherche binaire | égalité au floor, u64 sous $32 d < 2^{41}$ (une ligne) |
| `spindle_sector_d` | `bisector_basis` + test secteur DI128 | fixture classes 0..10, verdict et compte |
| `cell_grid_d` | Gram i64, det DI128, deux pointeurs DI128 toujours (le chemin i64 hôte est une optimisation) | égalité de `cnt[16][16]` par ancre |
| `di_to_double_d` | décalage à droite de k bits avec bit collant, valeur ≤ 64 bits, `(double)u64` (64 ≥ 53 + 2 : garde + collant), `ldexp` exact ; **un seul arrondi** | preuve écrite `proof_internal` dans `docs/math/STATUT_PREUVES_ET_HEURISTIQUES.md` (la fixture seule ne couvre pas les 2^127 milieux) + porte bit à bit contre `(double)(__int128)` |
| `seed_affine_d` | N0..N2, G, l_exact + doubles formés sur device | séquence FMA figée sous `-fmad=false`, arrondi au plus proche, `--use_fast_math` refusé à la compilation |
| `isqrt128_floor_d` | v < 2^120 : `sqrt(double)` a une erreur absolue ≈ 2^8–2^9, un « ±1 » est **faux** ; estimation, un pas de Newton entier en DI128, puis boucle de correction **bornée** (≤ 2^10 pas, `di_mul_i64_i64(r, r)` valide car r < 2^63) | preuve de la borne ; sans elle la corde n'est pas conservatrice et le kill n'est pas certifié |
| histogrammes de coins device | `in_spindle_d` | égalité des histogrammes par rectangle |

**Restent hôte** : `ugcd128`, `ball_key_reduce`, `rational_reduce`, `promote_level`, `q2_ball_key`. Coût réel 1–3 µs par survivant (pgcd binaire de 5 i128 + `q4_form` i128 + 4 lectures aléatoires de `upos`), pas 0,3 µs : 50 k ≈ 0,5–1,3 s ; 10 M ≈ 4,3 G × 4 défauts de cache × 100 ns / 48 ≈ 6 min, du même ordre que le gain revendiqué ; à mesurer.

**Filtre flottant** : uniquement `q3_l_hat_shaped`, `jung_interval_sign_shaped`, `locate` ; chaque usage a son repli exact. Interdit : flottant sans repli, comparaison de niveau par hash ou `==`.

**Replis** : `na² + nb²`, arène, lentille, `cand_cap` → rejoués par le corps hôte de production, `routed_host` exposé ; mutant `overflow-drop` (ignorer un overflow) tué sur une fixture qui **force** l'overflow d'arène (cover = n avec `arena_sites_per_block` réduit en mode porte) et de K1.

**Déterminisme** :
- Objet : multiensemble des `CandD` → `BallCandidate` → `rle_candidates` → `digest_balls_v4`. Porte principale = **digest identique cpu/gpu**, cinq familles, s = 6/8/10, n = 8000/16000/32000/50000.
- Ordre brut : non spécifié à T > 1 (contrat existant). `--raw-order-gate` à T = 1 : `CandTaggedD` (rect, ua, ub, `seed_rank`, `lens_rank`), tri hôte, comparaison **du vecteur entier** avec la production à un fil.
- Compteurs, trois classes dans `GenerateStats` : *exacts, égalité exigée* (`rects`, `ancres_hist`, `ancres_w3/w4`, `ancres_secteurs`, `grids_attempted/built`, `seeds_acute`, `seeds_killed_cells`, `seeds_alive`, `jneg`, `pairs_tested`, `owned`, `exact_once`, `center_strict`, `depth_killed`, `emis`) ; *exacts sous ordre radial reproduit* (`cert_neg/cert_pos/fallback/jung_*/chord_*`, porte `strict` par défaut) ; *politique/mesure* (`visits`, `cover_nodes`, `routed_host`, `max_lot_*`, `Log2Hist`, `kernel_ms`, occupation, blocs actifs par SM via `%smid`, mutant `single-block`).
- Frontières de lots : verdict fonction pure (rectangle, index) ; `--lot-gate` : deux découpages (2^18 et 2^12 rects) → digest égal.
- Flottant : `-fmad=false -prec-div=true -prec-sqrt=true`, pas de fast-math, arrondi au plus proche, aucune somme de doubles dans un verdict.
- Mutants device : `MHGP5_MUTANT_D("nom")` résolu en **index constexpr** dans `kMutants` (règle `grep MHGP5_MUTANT` = `kMutants`, `mutants.hpp:12-13`), masque `__constant__ u32 g_mutant_mask` chargé par lot. Aujourd'hui `mutants.hpp:126-127` résout tout mutant à `(false)` sous `__CUDA_ARCH__` : **aucun mutant device n'existe** ; trou à consigner dans `audits/ETAT_COURANT.md` avant L7a.

## 7. Modèle de temps chiffré (budgets, à mesurer par le banc contrebalancé)

Hypothèses corrigées : débit entier GB202 ≈ 188 SM × 64 INT32/clk × 2,5 GHz ≈ 30 T instr/s crête ; ≈ 40 instr par visite (bin sans division) → 0,25–0,75 T visites/s à pleine occupation, 0,12–0,4 T/s à 2 blocs/SM tant que l'occupation n'est pas mesurée. K2 balaie les **visites** (`Σ handle_points`), pas le cover accepté ; le ratio `visites / cover` n'est ni imprimé ni connu (les lectures disponibles sont incohérentes entre elles) : **exposer `visits`, `cover_nodes` et la distribution des covers sur l'hôte est un verrou d'entrée de L7a**, pas une note. D2H : le reçu 12 mesure 1,35 Go/s sur le même bus ; 20 Go/s pinned est plausible et **à sonder isolément**.
