# Compactage de onze suivis historiques

Source : `CONSTATS.md` à `9c9c25893ca36022b702a55e837afac7794842a9`. Cette proposition modifie seulement la dixième cellule de onze lignes. Les 75 IDs, leur ordre, leurs états et les neuf premières colonnes restent identiques ; aucun code ni périmètre de qualification ne change. Les suivis récents 0018/0105/0107/0022/0207 et les huit suivis de la précédente archive sont exclus.

Registre : **51,460 → 48,272 octets**, soit **3,188 octets libérés**. Canal au pin : **63,886 → 60,698 octets**, avant toute révision indépendante des notes. Les cellules courtes relient chacune leur historique ci-dessous. Les liens de clôture sont conservés, avec leurs destinations rétablies relativement au présent reçu. Le texte antérieur est reproduit intégralement ; il décrit son périmètre et sa date, sans nouvelle réévaluation de ses affirmations.

`proposition.json` porte le SHA-256 source, le hash de chaque préfixe de ligne et de l'ancien suivi, ainsi que les nouveaux suivis. `verifier.py` relit le commit, confronte mot pour mot les anciens textes à cette table (seuls les chemins relatifs sont adaptés), vérifie tous les liens et produit facultativement un patch à contexte nul. Il n'applique rien. Les contrôles normal/−O sont consignés dans `verifications.json` ; ils portent sur conservation et structure, jamais sur les preuves scientifiques.

Depuis la racine du dépôt :

```sh
python -B morsehgp3D_v12/receipts/audit_canal_20261008/suivis_9c9c/verifier.py --repo . --patch /tmp/suivis_9c9c.patch
python -B -O morsehgp3D_v12/receipts/audit_canal_20261008/suivis_9c9c/verifier.py --repo .
git apply --check --unidiff-zero /tmp/suivis_9c9c.patch
```

L'intégrateur relira le diff et exécutera `tools/check_constats.py --hygiene` sur le canal final. Aucune mutation du canal vivant ni commit par cette proposition.
