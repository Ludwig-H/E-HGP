# Raccord catalogue du q4 différé

Lecture indépendante du commit `ffc2ff95f0ae7296bdc522df81df34c58c3fdf47`, sans build ni exécution du produit. Aucun défaut concret trouvé dans le raccord examiné. La qualification native/G4 de ce nouveau port reste une porte distincte.

Les 24 copies de [source](source/) ont été comparées aux objets Git de ce commit, puis aux fichiers du développeur lors de la fermeture. [SOURCE_BEFORE.json](SOURCE_BEFORE.json), [SOURCE_AFTER.json](SOURCE_AFTER.json) et [BASELINE_PINS.json](BASELINE_PINS.json) fixent les empreintes. L'échec initial de capture, dû à un chemin de pins erroné, est conservé dans [capture_error.json](capture_error.json) ; les copies déjà présentes ont été validées puis conservées. Ce n'est pas un échec produit.

La propriété des compteurs se déduit aussi sans géométrie : une présentation q4 possède quatre SiteIdx valides ; tout support canonique d'arité 2 ou 3 porte au moins une sentinelle et ne peut donc lui être égal. Une matérialisation q4 admise a nécessairement `qmin=4`. Un unique S* et un unique propriétaire donnent une matérialisation par boule qmin4 **sur une passe réussie**. Les deux passes paient ces opérations deux fois ; le ledger publié décrit une passe logique, sans nouvelle borne sur le nombre de candidats ni sur le temps.

Cette égalité est limitée au succès : un refus Collector peut survenir après une matérialisation et avant l'émission. Il n'existe alors aucun catalogue publié auquel attribuer le compteur de brouillon. Ce comportement reste conforme au contrat de refus complet.

[check.py](check.py) contrôle les captures et les pins, 525 comparaisons de supports remplis de sentinelles et neuf présentations abstraites. Il distingue le succès de la branche de refus après matérialisation. Ce modèle de compteurs n'exécute ni ne qualifie le catalogue natif ; les garanties géométriques ci-dessus sont des conclusions de lecture, sous les contrats numériques et K-certification existants. Les cas natifs annoncés dans les sources de tests restent à qualifier dans leur environnement autorisé.

Commandes locales : `python3 -B record.py` une fois pour fermer l'observation ; `python3 -B check.py` et `python3 -B -O check.py` pour le lecteur autonome. Les sorties sont enregistrées et identiques ; le lecteur fonctionne sans Git ni checkout développeur une fois le reçu fermé. `SHA256SUMS` couvre tous les payloads, hors lui-même.
